B-Tree와 B+Tree — 원리부터 자바 구현, DB 인덱스까지

둘 다 "디스크에서도 빠르게 찾기 위한" 균형 트리다. 이진 탐색 트리와 뭐가 다르고, 왜 데이터베이스 인덱스는 거의 다 B+Tree를 쓰는지, 노드가 어떻게 쪼개지고 합쳐지는지를 실제로 동작하는 자바 코드와 함께 끝까지 뜯어본다.

01왜 이진 탐색 트리로는 부족한가

디스크 접근 횟수가 진짜 비용이다

이진 탐색 트리(BST)는 메모리 안에서는 빠르다. 문제는 데이터베이스가 다루는 테이블은 메모리에 다 못 올리는 크기라, 인덱스 자체도 디스크에 저장돼 있다는 것이다. 트리를 한 칸 내려갈 때마다 디스크 블록 하나를 읽어야 한다면, 트리의 높이가 곧 디스크 접근 횟수가 된다.

균형 잡힌 이진 트리라도 원소가 100만 개면 높이는 log₂(1,000,000) ≈ 20. 디스크 접근 20번(각각 수 ms)이면 검색 한 번에 수십 ms — 느리다. 반면 노드 하나가 자식을 수백 개 가질 수 있다면(다진 트리, multi-way tree) 같은 100만 개를 훨씬 낮은 높이로 담을 수 있다. B-Tree와 B+Tree는 바로 이 "노드 하나 = 디스크 블록 하나, 그 안에 최대한 많은 키를 욱여넣자"는 발상에서 나왔다.

핵심

노드의 자식 수(차수)를 늘릴수록 트리 높이는 줄어들고, 높이가 줄어들수록 디스크 접근 횟수가 줄어든다. B-Tree/B+Tree는 "한 노드 = 한 디스크 페이지"가 되도록 차수를 최대한 키운 균형 다진 탐색 트리다.

02B-Tree 구조와 용어

최소 차수 t (minimum degree)

이 노트의 구현은 CLRS(《Introduction to Algorithms》) 방식대로 최소 차수 t로 용량을 정의한다.

항목규칙
노드당 최대 키 수2t − 1
노드당 최소 키 수t − 1 (단, 루트는 예외 — 최소 1개만 있어도 됨)
내부 노드의 자식 수키 개수 + 1 (즉 최소 t개, 최대 2t개)
리프의 깊이모든 리프가 정확히 같은 깊이에 있다
데이터 저장 위치모든 노드 (내부 노드에도 값이 함께 저장된다)

"리프가 항상 같은 깊이"라는 게 균형의 핵심이다. 삽입/삭제 때마다 이 불변식이 깨지지 않도록 분할(split)·병합(merge)·재분배(borrow)를 한다.

삽입: 선제적 분할(proactive split)

루트부터 리프까지 내려가면서, 꽉 찬 노드를 만나면 들어가기 전에 미리 쪼갠다. 이렇게 하면 삽입 후 "다시 올라오면서 분할을 전파"할 필요가 없어 한 번의 하향 순회로 끝난다.

삭제: 선행자/후행자 대체, 빌리기, 병합

지우려는 키가 리프에 있으면 그냥 지우면 된다. 문제는 내부 노드에 있을 때다 — 그 자리를 비워두면 자식 포인터 개수와 안 맞으니, 세 가지 중 하나를 한다.

  1. 왼쪽 자식이 여유(≥ t개)가 있으면 — 그 자식의 가장 큰 값(선행자, predecessor)을 가져와 자리를 채우고, 선행자를 그 자식에서 재귀적으로 지운다.
  2. 왼쪽은 부족하고 오른쪽 자식이 여유가 있으면 — 후행자(successor, 오른쪽 서브트리의 최솟값)로 채운다.
  3. 둘 다 최소 크기(t-1개)면 — 두 자식을 삭제할 키와 함께 하나로 병합하고, 병합된 노드에서 재귀적으로 지운다.

또, 리프까지 내려가는 경로에서 지나가는 자식이 최소 크기(t-1개)라면 미리 손을 본다. 형제가 여유 있으면 하나 빌려오고(rotate), 형제도 최소 크기면 형제와 병합한다 — 이렇게 해야 "내려가서 지웠더니 그 노드가 규칙 미달"이 되는 상황을 막을 수 있다.

구현 시 흔한 실수

병합(merge)이 일어나면 부모의 자식 개수가 하나 줄어든다. 삭제를 재귀로 구현할 때 "몇 번째 자식으로 내려갈지" 인덱스를 병합 이전 기준으로 써버리면 엉뚱한 자식으로 내려가거나 범위를 벗어난다. 이 노트의 deleteInternal()에서 lastChild 플래그로 이 경우를 따로 처리하는 이유가 그것이다.

03B-Tree 자바 구현

search / insert / delete 전체 — TreeMap과 대조해 60,000회 무작위 검증 완료

BTree.java
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;

/**
 * B-Tree (최소 차수 t, CLRS 정의 기준)
 *
 * 규칙:
 *  - 루트를 제외한 모든 노드는 키를 최소 t-1개, 최대 2t-1개 가진다.
 *  - 리프가 아닌 노드의 자식 수는 (키 개수 + 1) 이다. 즉 최소 t개, 최대 2t개.
 *  - 모든 리프는 같은 깊이에 있다 (완벽하게 균형 잡힌 트리).
 *  - 키와 함께 값(V)도 모든 노드(리프뿐 아니라 내부 노드에도)에 저장된다 — 이것이 B+Tree와의 핵심 차이.
 *
 * insert: 항상 리프에서 시작해 아래에서 위로 커진다. 노드가 꽉 찬 상태로 내려가면
 *         먼저 그 노드를 분할(split)한 뒤 내려간다 ("선제적 분할" 방식이라 재귀 중 되돌아올 필요가 없다).
 * delete: CLRS 표준 알고리즘. 내부 노드의 키를 지울 때는 선행자/후행자로 대체하거나
 *         자식을 병합해서 문제를 리프까지 떠넘긴 뒤 처리한다.
 */
public class BTree<K extends Comparable<K>, V> {

    private final int t; // 최소 차수 (t >= 2)
    private Node root;

    private class Node {
        List<K> keys = new ArrayList<>();
        List<V> vals = new ArrayList<>();
        List<Node> children = new ArrayList<>();
        boolean leaf = true;

        boolean isFull() { return keys.size() == 2 * t - 1; }
    }

    public BTree(int t) {
        if (t < 2) throw new IllegalArgumentException("최소 차수 t는 2 이상이어야 합니다.");
        this.t = t;
        this.root = new Node();
    }

    // ================= 검색 =================

    public V search(K key) {
        return search(root, key);
    }

    private V search(Node node, K key) {
        int i = 0;
        while (i < node.keys.size() && key.compareTo(node.keys.get(i)) > 0) i++;
        if (i < node.keys.size() && key.compareTo(node.keys.get(i)) == 0) {
            return node.vals.get(i);
        }
        if (node.leaf) return null;
        return search(node.children.get(i), key);
    }

    public boolean contains(K key) {
        return search(key) != null;
    }

    // ================= 삽입 =================

    public void insert(K key, V value) {
        if (root.isFull()) {
            Node newRoot = new Node();
            newRoot.leaf = false;
            newRoot.children.add(root);
            splitChild(newRoot, 0);
            root = newRoot;
        }
        insertNonFull(root, key, value);
    }

    /** parent.children.get(i) 는 꽉 찬 노드(2t-1개 키)라고 가정하고 둘로 쪼갠다. */
    private void splitChild(Node parent, int i) {
        Node child = parent.children.get(i);
        Node sibling = new Node();
        sibling.leaf = child.leaf;

        int mid = t - 1; // 중앙 인덱스 (0-based, 총 2t-1개 중 t-1번째)

        // 중앙 뒤쪽 절반은 새 형제 노드로 이동
        sibling.keys.addAll(child.keys.subList(mid + 1, child.keys.size()));
        sibling.vals.addAll(child.vals.subList(mid + 1, child.vals.size()));

        K midKey = child.keys.get(mid);
        V midVal = child.vals.get(mid);

        if (!child.leaf) {
            sibling.children.addAll(child.children.subList(mid + 1, child.children.size()));
            trimList(child.children, mid + 1);
        }

        // child는 왼쪽 절반(중앙 포함 전까지)만 남긴다
        trimList(child.keys, mid);
        trimList(child.vals, mid);

        parent.children.add(i + 1, sibling);
        parent.keys.add(i, midKey);
        parent.vals.add(i, midVal);
    }

    private void insertNonFull(Node node, K key, V value) {
        int idx = 0;
        while (idx < node.keys.size() && key.compareTo(node.keys.get(idx)) > 0) idx++;

        if (idx < node.keys.size() && key.compareTo(node.keys.get(idx)) == 0) {
            node.vals.set(idx, value); // 이미 있는 키 -> 값 갱신
            return;
        }

        if (node.leaf) {
            node.keys.add(idx, key);
            node.vals.add(idx, value);
            return;
        }

        Node child = node.children.get(idx);
        if (child.isFull()) {
            splitChild(node, idx);
            // 분할로 node.keys.get(idx) 자리에 새 중앙키가 생겼으니 다시 비교
            if (key.compareTo(node.keys.get(idx)) > 0) {
                idx++;
            } else if (key.compareTo(node.keys.get(idx)) == 0) {
                node.vals.set(idx, value);
                return;
            }
        }
        insertNonFull(node.children.get(idx), key, value);
    }

    // ================= 삭제 =================

    public void delete(K key) {
        deleteInternal(root, key);
        if (root.keys.isEmpty() && !root.leaf) {
            root = root.children.get(0); // 루트가 비면 유일한 자식을 새 루트로
        }
    }

    private void deleteInternal(Node node, K key) {
        int idx = 0;
        while (idx < node.keys.size() && key.compareTo(node.keys.get(idx)) > 0) idx++;

        if (idx < node.keys.size() && key.compareTo(node.keys.get(idx)) == 0) {
            if (node.leaf) {
                node.keys.remove(idx);
                node.vals.remove(idx);
            } else {
                deleteFromInternalNode(node, idx);
            }
            return;
        }

        if (node.leaf) return; // 키가 트리에 없음

        boolean lastChild = (idx == node.keys.size());
        if (node.children.get(idx).keys.size() < t) {
            fill(node, idx);
        }
        // fill()에서 병합이 일어나면 idx가 가리키는 자식 구성이 바뀔 수 있어 보정
        if (lastChild && idx > node.keys.size()) {
            deleteInternal(node.children.get(idx - 1), key);
        } else {
            deleteInternal(node.children.get(idx), key);
        }
    }

    /** node.keys.get(idx) 를 지운다 (node는 리프가 아님을 전제). */
    private void deleteFromInternalNode(Node node, int idx) {
        K key = node.keys.get(idx);
        Node leftChild = node.children.get(idx);
        Node rightChild = node.children.get(idx + 1);

        if (leftChild.keys.size() >= t) {
            // 선행자(predecessor)로 대체
            Node cur = leftChild;
            while (!cur.leaf) cur = cur.children.get(cur.children.size() - 1);
            K predKey = cur.keys.get(cur.keys.size() - 1);
            V predVal = cur.vals.get(cur.vals.size() - 1);
            node.keys.set(idx, predKey);
            node.vals.set(idx, predVal);
            deleteInternal(leftChild, predKey);
        } else if (rightChild.keys.size() >= t) {
            // 후행자(successor)로 대체
            Node cur = rightChild;
            while (!cur.leaf) cur = cur.children.get(0);
            K succKey = cur.keys.get(0);
            V succVal = cur.vals.get(0);
            node.keys.set(idx, succKey);
            node.vals.set(idx, succVal);
            deleteInternal(rightChild, succKey);
        } else {
            // 양쪽 다 최소 크기 -> 두 자식을 key와 함께 병합
            mergeChildren(node, idx);
            deleteInternal(leftChild, key);
        }
    }

    /** node.children.get(idx) 가 최소 크기 미만이면 형제에게서 빌리거나 병합해서 크기를 t 이상으로 만든다. */
    private void fill(Node node, int idx) {
        if (idx != 0 && node.children.get(idx - 1).keys.size() >= t) {
            borrowFromPrev(node, idx);
        } else if (idx != node.keys.size() && node.children.get(idx + 1).keys.size() >= t) {
            borrowFromNext(node, idx);
        } else {
            if (idx != node.keys.size()) {
                mergeChildren(node, idx);
            } else {
                mergeChildren(node, idx - 1);
            }
        }
    }

    private void borrowFromPrev(Node node, int idx) {
        Node child = node.children.get(idx);
        Node sibling = node.children.get(idx - 1);

        child.keys.add(0, node.keys.get(idx - 1));
        child.vals.add(0, node.vals.get(idx - 1));
        if (!child.leaf) {
            child.children.add(0, sibling.children.remove(sibling.children.size() - 1));
        }

        node.keys.set(idx - 1, sibling.keys.remove(sibling.keys.size() - 1));
        node.vals.set(idx - 1, sibling.vals.remove(sibling.vals.size() - 1));
    }

    private void borrowFromNext(Node node, int idx) {
        Node child = node.children.get(idx);
        Node sibling = node.children.get(idx + 1);

        child.keys.add(node.keys.get(idx));
        child.vals.add(node.vals.get(idx));
        if (!child.leaf) {
            child.children.add(sibling.children.remove(0));
        }

        node.keys.set(idx, sibling.keys.remove(0));
        node.vals.set(idx, sibling.vals.remove(0));
    }

    /** node.children[idx] 와 node.children[idx+1] 을 node.keys[idx]와 함께 하나로 합친다. */
    private void mergeChildren(Node node, int idx) {
        Node left = node.children.get(idx);
        Node right = node.children.get(idx + 1);

        left.keys.add(node.keys.remove(idx));
        left.vals.add(node.vals.remove(idx));
        left.keys.addAll(right.keys);
        left.vals.addAll(right.vals);
        if (!left.leaf) {
            left.children.addAll(right.children);
        }
        node.children.remove(idx + 1);
    }

    private static <E> void trimList(List<E> list, int fromIndex) {
        list.subList(fromIndex, list.size()).clear();
    }

    // ================= 출력 (레벨 순회) =================

    /** 레벨별로 각 노드의 키 목록을 출력한다. 트리 구조를 눈으로 확인할 때 사용. */
    public void printLevels() {
        Queue<Node> queue = new LinkedList<>();
        queue.add(root);
        int level = 0;
        while (!queue.isEmpty()) {
            int levelSize = queue.size();
            StringBuilder sb = new StringBuilder("L" + level + ": ");
            for (int i = 0; i < levelSize; i++) {
                Node node = queue.poll();
                sb.append(node.keys).append("  ");
                if (!node.leaf) queue.addAll(node.children);
            }
            System.out.println(sb.toString().trim());
            level++;
        }
    }

    /** 중위 순회로 키를 오름차순 정렬해서 반환한다 (검증용). */
    public List<K> inorderKeys() {
        List<K> result = new ArrayList<>();
        inorder(root, result);
        return result;
    }

    private void inorder(Node node, List<K> out) {
        for (int i = 0; i < node.keys.size(); i++) {
            if (!node.leaf) inorder(node.children.get(i), out);
            out.add(node.keys.get(i));
        }
        if (!node.leaf) inorder(node.children.get(node.keys.size()), out);
    }

    // ================= 데모 =================

    public static void main(String[] args) {
        BTree<Integer, String> tree = new BTree<>(3); // t=3 -> 노드당 최대 5개 키, 최대 6개 자식

        int[] keys = {10, 20, 5, 6, 12, 30, 7, 17, 3, 25, 1, 40, 15, 8, 22};
        for (int k : keys) tree.insert(k, "v" + k);

        System.out.println("=== 삽입 후 레벨별 구조 (t=3) ===");
        tree.printLevels();

        System.out.println("\n=== 검색 테스트 ===");
        System.out.println("search(17) = " + tree.search(17));
        System.out.println("search(99) = " + tree.search(99));

        System.out.println("\n=== 삭제: 6, 12, 30 ===");
        tree.delete(6);
        tree.delete(12);
        tree.delete(30);
        tree.printLevels();

        System.out.println("\n=== 중위 순회 (정렬 확인) ===");
        System.out.println(tree.inorderKeys());
    }
}

04B+Tree — 무엇이, 왜 다른가

데이터는 리프에만, 내부 노드는 이정표일 뿐

B-Tree와 구조는 비슷하지만 세 가지가 다르다.

항목B-TreeB+Tree
데이터(값) 저장 위치모든 노드리프에만
내부 노드의 키실제 데이터를 가리킴리프 키를 복사한 라우팅 정보일 뿐
리프끼리 연결없음오른쪽 리프를 가리키는 연결 리스트
구간(range) 조회트리를 오르내리며 순회리프 체인만 옆으로 훑으면 끝
같은 키 개수일 때 트리 높이더 낮을 수 있음(내부에도 데이터)내부 노드가 순수 라우팅이라 같은 페이지 크기에 더 많은 키를 욱여넣어 대개 더 낮음

리프 분할: 복사(copy-up), 내부 분할: 이동(move-up)

리프가 넘치면 오른쪽 절반을 새 리프로 옮기고, 오른쪽 리프의 첫 키를 그대로 복사해서 부모에 올린다 — 원본은 리프에 남는다(데이터 유실 방지). 반면 내부 노드가 넘치면, 중앙 키를 부모로 이동시키고 원래 자리에서는 제거한다 (내부 노드는 라우팅용이라 중복 보관할 이유가 없다). B+Tree 코드에서 리프 분할과 내부 분할의 로직이 미묘하게 다른 이유가 이것이다.

이래서 range 조회가 빠르다

WHERE age BETWEEN 20 AND 30 같은 질의를 생각해보면, B-Tree는 값이 내부 노드에도 흩어져 있어서 순회 중 여러 번 트리를 오르내려야 할 수 있다. B+Tree는 findLeaf(20)으로 시작점만 한 번 찾은 뒤, 그다음부터는 next 포인터만 따라가며 리프를 순서대로 읽으면 끝 — 정렬된 배열을 순차로 읽는 것과 비용이 비슷하다.

05B+Tree 자바 구현

search / insert / delete / rangeSearch — 45,000회 무작위 검증 완료

BPlusTree.java
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;

/**
 * B+Tree (order = 내부 노드의 최대 자식 수 m)
 *
 * B-Tree와의 핵심 차이:
 *  - 실제 데이터(값 V)는 오직 리프 노드에만 저장된다. 내부 노드는 "이정표(routing key)" 역할만 한다.
 *  - 모든 리프는 오른쪽 형제를 가리키는 연결 리스트로 이어져 있다 -> 구간(range) 조회가
 *    루트로 돌아올 필요 없이 리프만 옆으로 훑으면 끝난다. 이게 DB 인덱스에서 B+Tree를 쓰는 이유다.
 *  - 내부 노드의 키는 리프에도 "복사"되어 있는 것이라, 내부 노드 키를 지워도 실제 데이터는
 *    사라지지 않는다 (라우팅 정보일 뿐).
 *
 * 용량 정의(이 구현 기준):
 *  - 내부 노드: 최대 자식 m개 -> 최대 키 m-1개, 최소 자식 ceil(m/2)개 -> 최소 키 ceil(m/2)-1개 (루트 제외)
 *  - 리프 노드: 최대 키(엔트리) m-1개, 최소 키 floor(m/2)개 (루트 제외)
 */
public class BPlusTree<K extends Comparable<K>, V> {

    private final int order; // m
    private Node root;

    private class Node {
        boolean leaf;
        List<K> keys = new ArrayList<>();
        List<V> values = new ArrayList<>();      // leaf에서만 사용
        List<Node> children = new ArrayList<>();  // internal에서만 사용
        Node next;                                 // leaf에서만 사용 (오른쪽 리프로의 연결)
        Node parent;

        Node(boolean leaf) { this.leaf = leaf; }
    }

    public BPlusTree(int order) {
        if (order < 3) throw new IllegalArgumentException("order는 3 이상이어야 합니다.");
        this.order = order;
        this.root = new Node(true);
    }

    private int minLeafKeys() { return order / 2; }
    private int minInternalKeys() { return (order + 1) / 2 - 1; }

    // ================= 검색 =================

    private Node findLeaf(K key) {
        Node cur = root;
        while (!cur.leaf) {
            int i = 0;
            // key < keys[i] 인 첫 위치를 찾는다 (동점이면 오른쪽 서브트리로 -> split 시 "복사 후 올림" 규칙과 짝을 맞춤)
            while (i < cur.keys.size() && key.compareTo(cur.keys.get(i)) >= 0) i++;
            cur = cur.children.get(i);
        }
        return cur;
    }

    public V search(K key) {
        Node leaf = findLeaf(key);
        int idx = indexOfKey(leaf.keys, key);
        return idx >= 0 ? leaf.values.get(idx) : null;
    }

    public boolean contains(K key) { return search(key) != null; }

    /** [low, high] 구간의 (key, value)를 오름차순으로 반환한다 — 리프 연결 리스트만 타고 가는 range scan. */
    public List<java.util.Map.Entry<K, V>> rangeSearch(K low, K high) {
        List<java.util.Map.Entry<K, V>> result = new ArrayList<>();
        Node leaf = findLeaf(low);
        while (leaf != null) {
            for (int i = 0; i < leaf.keys.size(); i++) {
                K k = leaf.keys.get(i);
                if (k.compareTo(low) < 0) continue;
                if (k.compareTo(high) > 0) return result;
                result.add(java.util.Map.entry(k, leaf.values.get(i)));
            }
            leaf = leaf.next;
        }
        return result;
    }

    private int indexOfKey(List<K> keys, K key) {
        for (int i = 0; i < keys.size(); i++) {
            int c = key.compareTo(keys.get(i));
            if (c == 0) return i;
            if (c < 0) return -1;
        }
        return -1;
    }

    // ================= 삽입 =================

    public void insert(K key, V value) {
        Node leaf = findLeaf(key);
        int pos = 0;
        while (pos < leaf.keys.size() && key.compareTo(leaf.keys.get(pos)) > 0) pos++;
        if (pos < leaf.keys.size() && key.compareTo(leaf.keys.get(pos)) == 0) {
            leaf.values.set(pos, value); // 이미 있는 키 -> 값 갱신
            return;
        }
        leaf.keys.add(pos, key);
        leaf.values.add(pos, value);

        if (leaf.keys.size() > order - 1) {
            splitLeaf(leaf);
        }
    }

    private void splitLeaf(Node leaf) {
        Node right = new Node(true);
        int mid = leaf.keys.size() / 2; // 왼쪽에 mid개, 오른쪽에 나머지

        right.keys.addAll(leaf.keys.subList(mid, leaf.keys.size()));
        right.values.addAll(leaf.values.subList(mid, leaf.values.size()));
        trim(leaf.keys, mid);
        trim(leaf.values, mid);

        right.next = leaf.next;
        leaf.next = right;
        right.parent = leaf.parent;

        K upKey = right.keys.get(0); // 오른쪽 리프의 첫 키를 그대로 "복사"해서 부모로 올린다 (데이터는 리프에 남음)
        insertIntoParent(leaf, upKey, right);
    }

    /** left의 부모에 (upKey, right) 쌍을 끼워 넣는다. 부모가 없으면 새 루트를 만든다. */
    private void insertIntoParent(Node left, K upKey, Node right) {
        Node parent = left.parent;
        if (parent == null) {
            Node newRoot = new Node(false);
            newRoot.keys.add(upKey);
            newRoot.children.add(left);
            newRoot.children.add(right);
            left.parent = newRoot;
            right.parent = newRoot;
            root = newRoot;
            return;
        }

        int idx = parent.children.indexOf(left);
        parent.keys.add(idx, upKey);
        parent.children.add(idx + 1, right);
        right.parent = parent;

        if (parent.keys.size() > order - 1) {
            splitInternal(parent);
        }
    }

    private void splitInternal(Node node) {
        int mid = node.keys.size() / 2;
        K upKey = node.keys.get(mid); // 내부 노드는 중앙 키를 "위로 올리고 제거" (리프와 달리 복사가 아님)

        Node right = new Node(false);
        right.keys.addAll(node.keys.subList(mid + 1, node.keys.size()));
        right.children.addAll(node.children.subList(mid + 1, node.children.size()));
        for (Node c : right.children) c.parent = right;

        trim(node.keys, mid); // mid 포함 이후 제거 (mid는 upKey로 이미 빼감)
        trim(node.children, mid + 1);

        right.parent = node.parent;
        insertIntoParent(node, upKey, right);
    }

    private static <E> void trim(List<E> list, int fromIndex) {
        list.subList(fromIndex, list.size()).clear();
    }

    // ================= 삭제 =================

    public boolean delete(K key) {
        Node leaf = findLeaf(key);
        int idx = indexOfKey(leaf.keys, key);
        if (idx < 0) return false;

        leaf.keys.remove(idx);
        leaf.values.remove(idx);

        if (leaf == root) return true; // 루트가 곧 리프면 최소 크기 제약 없음
        if (leaf.keys.size() < minLeafKeys()) fixLeafUnderflow(leaf);
        return true;
    }

    private void fixLeafUnderflow(Node leaf) {
        Node parent = leaf.parent;
        int idx = parent.children.indexOf(leaf);
        Node leftSib = idx > 0 ? parent.children.get(idx - 1) : null;
        Node rightSib = idx < parent.children.size() - 1 ? parent.children.get(idx + 1) : null;

        if (leftSib != null && leftSib.keys.size() > minLeafKeys()) {
            int last = leftSib.keys.size() - 1;
            leaf.keys.add(0, leftSib.keys.remove(last));
            leaf.values.add(0, leftSib.values.remove(last));
            parent.keys.set(idx - 1, leaf.keys.get(0));
        } else if (rightSib != null && rightSib.keys.size() > minLeafKeys()) {
            leaf.keys.add(rightSib.keys.remove(0));
            leaf.values.add(rightSib.values.remove(0));
            parent.keys.set(idx, rightSib.keys.get(0));
        } else if (leftSib != null) {
            leftSib.keys.addAll(leaf.keys);
            leftSib.values.addAll(leaf.values);
            leftSib.next = leaf.next;
            parent.children.remove(idx);
            parent.keys.remove(idx - 1);
            fixInternalUnderflow(parent);
        } else if (rightSib != null) {
            leaf.keys.addAll(rightSib.keys);
            leaf.values.addAll(rightSib.values);
            leaf.next = rightSib.next;
            parent.children.remove(idx + 1);
            parent.keys.remove(idx);
            fixInternalUnderflow(parent);
        }
    }

    private void fixInternalUnderflow(Node node) {
        if (node == root) {
            if (node.keys.isEmpty() && !node.children.isEmpty()) {
                root = node.children.get(0);
                root.parent = null;
            }
            return;
        }
        if (node.keys.size() >= minInternalKeys()) return;

        Node parent = node.parent;
        int idx = parent.children.indexOf(node);
        Node leftSib = idx > 0 ? parent.children.get(idx - 1) : null;
        Node rightSib = idx < parent.children.size() - 1 ? parent.children.get(idx + 1) : null;

        if (leftSib != null && leftSib.keys.size() > minInternalKeys()) {
            node.keys.add(0, parent.keys.get(idx - 1));
            parent.keys.set(idx - 1, leftSib.keys.remove(leftSib.keys.size() - 1));
            Node moved = leftSib.children.remove(leftSib.children.size() - 1);
            moved.parent = node;
            node.children.add(0, moved);
        } else if (rightSib != null && rightSib.keys.size() > minInternalKeys()) {
            node.keys.add(parent.keys.get(idx));
            parent.keys.set(idx, rightSib.keys.remove(0));
            Node moved = rightSib.children.remove(0);
            moved.parent = node;
            node.children.add(moved);
        } else if (leftSib != null) {
            leftSib.keys.add(parent.keys.remove(idx - 1));
            leftSib.keys.addAll(node.keys);
            for (Node c : node.children) c.parent = leftSib;
            leftSib.children.addAll(node.children);
            parent.children.remove(idx);
            fixInternalUnderflow(parent);
        } else if (rightSib != null) {
            node.keys.add(parent.keys.remove(idx));
            node.keys.addAll(rightSib.keys);
            for (Node c : rightSib.children) c.parent = node;
            node.children.addAll(rightSib.children);
            parent.children.remove(idx + 1);
            fixInternalUnderflow(parent);
        }
    }

    // ================= 출력 =================

    public void printLevels() {
        Queue<Node> queue = new LinkedList<>();
        queue.add(root);
        int level = 0;
        while (!queue.isEmpty()) {
            int levelSize = queue.size();
            StringBuilder sb = new StringBuilder("L" + level + ": ");
            for (int i = 0; i < levelSize; i++) {
                Node node = queue.poll();
                sb.append(node.leaf ? "leaf" : "int").append(node.keys).append("  ");
                if (!node.leaf) queue.addAll(node.children);
            }
            System.out.println(sb.toString().trim());
            level++;
        }
    }

    /** 맨 왼쪽 리프부터 연결 리스트를 옆으로 훑어서 전체를 정렬된 순서로 반환한다 (검증/range scan 데모용). */
    public List<K> scanAllViaLeafChain() {
        Node cur = root;
        while (!cur.leaf) cur = cur.children.get(0);
        List<K> out = new ArrayList<>();
        while (cur != null) {
            out.addAll(cur.keys);
            cur = cur.next;
        }
        return out;
    }

    // ================= 데모 =================

    public static void main(String[] args) {
        BPlusTree<Integer, String> tree = new BPlusTree<>(4); // order=4 -> 내부 최대 자식 4, 리프 최대 엔트리 3

        int[] keys = {10, 20, 5, 6, 12, 30, 7, 17, 3, 25, 1, 40, 15, 8, 22};
        for (int k : keys) tree.insert(k, "v" + k);

        System.out.println("=== 삽입 후 레벨별 구조 (order=4) ===");
        tree.printLevels();

        System.out.println("\n=== 리프 연결 리스트로 전체 스캔 (정렬 확인) ===");
        System.out.println(tree.scanAllViaLeafChain());

        System.out.println("\n=== 구간 검색 rangeSearch(7, 22) ===");
        System.out.println(tree.rangeSearch(7, 22));

        System.out.println("\n=== 삭제: 6, 12, 30 ===");
        tree.delete(6);
        tree.delete(12);
        tree.delete(30);
        tree.printLevels();
        System.out.println("리프 체인 스캔: " + tree.scanAllViaLeafChain());
    }
}

아래는 같은 삽입·삭제·분할·병합 로직을 자바스크립트로 그대로 옮겨 브라우저 안에서 돌리는 시각화다(45,000회 무작위 연산으로 검증한 로직과 동일). 주황 박스가 내부(라우팅) 노드, 파란 박스가 리프(데이터) 노드, 리프 아래 점선이 range scan에 쓰이는 연결 리스트다.

07실제 DB에서 어떻게 쓰이는가

왜 인덱스는 거의 다 B+Tree인가

노드 크기 = 디스크 페이지 크기

실무 구현에서 노드(=페이지) 하나의 크기는 디스크/파일시스템의 블록 크기에 맞춘다. 예를 들어 MySQL InnoDB는 기본 페이지 크기 16KB를 쓴다. 정수형 PK(8바이트)와 포인터(6바이트 안팎)로 계산하면 내부 노드 하나가 대략 수백~천 개의 자식을 가질 수 있다. order가 1,000 근방이라면 100만 건도 트리 높이 2~3이면 충분히 담긴다 — 즉 디스크 접근 2~3번으로 어떤 행이든 찾을 수 있다.

항목대략적인 값(예시)
페이지 크기16 KB (InnoDB 기본값)
PK + 포인터 1쌍 크기약 10~20 바이트
페이지당 대략적인 fanout(자식 수)수백~1,000 이상
1억 건을 담는 데 필요한 트리 높이약 3~4단계

InnoDB의 클러스터드 인덱스(Clustered Index)

InnoDB는 기본 키(PK) 자체가 B+Tree이고, 리프에 행 데이터 전체가 들어있다 (이를 clustered index라 한다). 그래서 PK로 찾는 조회는 인덱스를 찾는 게 곧 데이터를 찾는 것과 같다 — 리프에 도달하면 바로 그 행의 모든 컬럼이 있다.

PK가 아닌 보조 인덱스(secondary index)는 별도의 B+Tree인데, 리프에 행 데이터 대신 PK 값을 저장한다. 그래서 보조 인덱스로 검색하면 "보조 인덱스 트리에서 PK를 찾고 → 그 PK로 클러스터드 인덱스를 한 번 더 탐색"하는 2단계 조회가 된다. 이를 Bookmark Lookup(또는 Random I/O)이라 부르며, 보조 인덱스로 많은 행을 긁는 쿼리가 느려지는 대표적인 이유다 — EXPLAIN에서 "Using index" 문구가 이 비용을 피했는지 알려준다(covering index).

범위 스캔·정렬·페이징이 빠른 이유

  • WHERE col BETWEEN a AND b — 시작 리프만 찾고 next 포인터로 쭉 읽는다 (섹션 04).
  • ORDER BY col — 인덱스가 이미 정렬돼 있으니 리프를 순서대로 읽기만 하면 별도 정렬(filesort)이 필요 없다.
  • LIMIT/OFFSET 페이징 — 인덱스 순서를 그대로 따라가면 되므로 별도 정렬 비용이 없다(단, OFFSET이 매우 크면 그만큼 리프를 건너뛰며 읽어야 해서 느려질 수 있다 — 이건 B+Tree 자체의 한계라기보다 OFFSET 방식의 한계).

왜 B-Tree가 아니라 B+Tree인가

B-Tree도 내부 노드에 데이터를 들고 있어서 "자주 찾는 상위 레벨 키는 오히려 더 빨리 찾을 수 있다"는 장점이 이론적으로는 있다. 하지만 DB는 다음 이유로 B+Tree를 압도적으로 선호한다.

  • 내부 노드가 데이터 없이 라우팅만 하니 같은 페이지 크기에 더 많은 키를 담아 fanout이 커지고, 트리가 더 낮아진다.
  • 리프 연결 리스트 덕분에 순차 스캔/범위 스캔이 트리 재순회 없이 가능하다.
  • 모든 검색이 항상 리프까지 내려가므로 탐색 시간이 일정하다(B-Tree는 운 좋으면 내부에서 바로 찾아지는 대신, 그만큼 최악·평균 케이스 편차가 생긴다).
이 노트의 한계

실제 DB 엔진은 여기에 더해 버퍼 풀(캐시), WAL(로그 선행 기입), 페이지 압축, 잠금·MVCC, 인덱스 페이지 채움율(fill factor) 조정, 우측 페이지 미리 분할 방지 최적화 등을 함께 쓴다. 이 노트의 자바 구현은 "핵심 자료구조 원리"만 정확히 재현한 학습용이고, 실제 스토리지 엔진 수준의 동시성·영속성 처리는 하지 않는다.
