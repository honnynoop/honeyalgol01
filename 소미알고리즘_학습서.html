01 들어가기 (Intro)

시간·공간 복잡도 분석 방법Time-Space Complexity Analysis Method

복잡도는 알고리즘이 입력 크기 n이 커질 때 실행 시간(시간 복잡도)과 메모리 사용량(공간 복잡도)이 어떻게 증가하는지를 나타내는 척도입니다. 실제 실행 시간(ms)은 하드웨어·언어·컴파일러에 따라 달라지므로, 알고리즘 자체의 효율성을 비교하려면 입력 크기 증가에 따른 연산 횟수의 증가 추세를 봐야 합니다. 이때 사용하는 표기법이 빅오(Big-O) 표기법입니다.

핵심 원리

  • Big-O(상한, O): 최악의 경우에도 이 이상 나빠지지 않는다는 상한선. 알고리즘 성능을 보수적으로 평가할 때 사용하며, 코딩테스트에서 가장 널리 쓰인다.
  • Big-Ω(하한, Omega): 최선의 경우 최소한 이만큼은 걸린다는 하한선.
  • Big-Θ(타이트 바운드, Theta): 상한과 하한이 같아 정확한 증가율을 나타낼 때 사용.
  • 복잡도 계산 시 최고차항만 남기고 계수와 하위항은 무시한다 (예: 3n² + 5n + 7 → O(n²)).
  • 반복문이 중첩되면 곱해지고(O(n)×O(n)=O(n²)), 순차적으로 나열되면 더해진 뒤 최고차항만 남는다(O(n)+O(n²)→O(n²)).

시간 복잡도 등급 (빠른 순)

표기이름n=10⁶일 때 대략 연산 수대표 예시
O(1)상수1배열 인덱스 접근, 해시맵 조회
O(log n)로그~20이분 탐색, 균형 트리 탐색
O(n)선형10⁶배열 순회, 선형 탐색
O(n log n)선형로그~2×10⁷병합/퀵 정렬, 이진힙 정렬
O(n²)이차10¹² (매우 느림)버블/선택 정렬, 이중 for문
O(2ⁿ)지수사실상 불가완전탐색 부분집합, 재귀 피보나치(비메모)
O(n!)팩토리얼사실상 불가순열 전체 탐색(외판원 문제 완전탐색)
실전 가이드: 코딩테스트에서 "시간 제한 1초 = 약 1억(10⁸)번 연산"을 기준으로 삼는다. n≤10⁵이면 O(n log n) 이하, n≤5000이면 O(n²), n≤500이면 O(n³), n≤20이면 O(2ⁿ)까지 허용된다고 가정하고 알고리즘을 설계한다.

공간 복잡도

알고리즘 실행에 필요한 메모리양이다. 입력 자체를 저장하는 공간(고정 공간)과 알고리즘 실행 중 추가로 사용하는 공간(가변 공간: 재귀 호출 스택, 보조 배열 등)으로 나뉜다. 재귀 함수는 호출 스택 깊이만큼 O(depth)의 공간을 추가로 사용한다는 점을 반드시 고려해야 한다.

Java 코드 예시 — 복잡도 측정 및 비교

import java.util.*;

public class ComplexityDemo {

    // O(n^2) — 이중 반복문, 모든 쌍을 비교
    static int countPairsON2(int[] arr) {
        int count = 0;
        for (int i = 0; i < arr.length; i++) {
            for (int j = i + 1; j < arr.length; j++) {
                if (arr[i] + arr[j] == 0) count++;
            }
        }
        return count;
    }

    // O(n) — 해시셋을 이용해 이중 반복을 단일 반복으로 축소 (시간 vs 공간 트레이드오프)
    static int countPairsON(int[] arr) {
        int count = 0;
        Map freq = new HashMap<>();
        for (int num : arr) {
            count += freq.getOrDefault(-num, 0);
            freq.merge(num, 1, Integer::sum);
        }
        return count;
    }

    public static void main(String[] args) {
        int[] arr = {1, -1, 2, -2, 3, 0};
        long t1 = System.nanoTime();
        System.out.println("O(n^2) 결과: " + countPairsON2(arr));
        long t2 = System.nanoTime();
        System.out.println("O(n) 결과: " + countPairsON(arr));
        long t3 = System.nanoTime();
        System.out.printf("O(n^2) 소요: %d ns, O(n) 소요: %d ns%n", (t2 - t1), (t3 - t2));
    }
}
활용: 문제를 풀기 전 입력 제약(n의 범위)을 먼저 확인하고 허용 복잡도를 역산하는 습관을 들이면, 처음부터 완전탐색이 아닌 적절한 알고리즘(이분탐색, DP, 그래프 알고리즘 등)을 선택할 수 있다.

파일 입출력File I/O

코딩테스트·백준 등에서는 표준입출력(System.in/System.out)을 사용하지만, 대용량 입력에서는 Scanner가 느려 시간초과가 발생하기 쉽다. 이를 해결하기 위해 BufferedReader/StringTokenizer와 BufferedWriter/StringBuilder를 조합해 입출력 성능을 최적화하는 것이 표준 패턴이다.

핵심 원리

  • Scanner는 내부적으로 정규식 파싱을 사용해 느리다 — 소규모 입력(수백 줄 이하)에만 적합.
  • BufferedReader는 버퍼에 한 줄씩 읽어들여 I/O 호출 횟수를 줄인다 — readLine()으로 한 줄씩, StringTokenizer로 공백 기준 토큰 분리.
  • System.out.println을 반복 호출하면 매번 flush가 발생해 느리다 — StringBuilder에 결과를 모아 마지막에 한 번에 출력하거나 BufferedWriter를 사용한다.
  • 파일 입출력이 필요한 경우 FileReader/FileWriter를 BufferedReader/BufferedWriter로 감싸 사용한다.

Java 코드 예시 — 고속 입출력 템플릿

import java.io.*;
import java.util.*;

public class FastIO {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringBuilder sb = new StringBuilder();

        int n = Integer.parseInt(br.readLine().trim());
        StringTokenizer st = new StringTokenizer(br.readLine());

        int[] arr = new int[n];
        for (int i = 0; i < n; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        for (int num : arr) {
            sb.append(num * 2).append('\n');
        }

        // 표준출력은 한 번만 호출 — System.out.print를 반복 호출하지 않는다
        System.out.print(sb);

        // 파일 입출력이 필요한 경우
        try (BufferedReader fileReader = new BufferedReader(new FileReader("input.txt"));
             BufferedWriter fileWriter = new BufferedWriter(new FileWriter("output.txt"))) {
            String line;
            while ((line = fileReader.readLine()) != null) {
                fileWriter.write(line.trim());
                fileWriter.newLine();
            }
        } catch (FileNotFoundException e) {
            // 파일이 없을 때 (테스트 환경에서는 무시 가능)
        }
    }
}
주의: br.readLine()은 개행 전까지 공백을 포함해 통째로 읽으므로, 숫자를 한 줄에 공백으로 구분해 여러 개 받을 때는 반드시 StringTokenizer 또는 split(" ")으로 재분리해야 한다.
활용: 입력 n이 10만 개 이상인 문제, 반복 출력이 많은 문제(예: 각 쿼리마다 결과 출력)에서는 반드시 BufferedReader + StringBuilder 조합을 기본값으로 사용한다.

02 자료 구조 (Data Structure)

배열Array

같은 자료형의 원소를 연속된 메모리 공간에 저장하는 가장 기본적인 자료구조. 인덱스로 O(1) 접근이 가능하지만, 크기가 고정되어 있고(Java에서는 생성 시 크기 확정) 중간 삽입/삭제 시 뒤의 원소를 모두 옮겨야 한다.

접근 O(1)
탐색 O(n)
삽입/삭제(중간) O(n)
삽입/삭제(끝) O(1)
int[] arr = new int[10];
int[][] matrix = new int[5][5];      // 2차원 배열
int[] copy = Arrays.copyOf(arr, arr.length * 2);  // 동적 확장은 복사 필요
Arrays.sort(arr);                     // O(n log n), 듀얼 피벗 퀵정렬
int idx = Arrays.binarySearch(arr, 5); // 정렬된 배열에서 O(log n)
활용: 크기가 미리 정해져 있고 랜덤 접근이 빈번한 경우(DP 테이블, 그래프의 인접행렬, 카운팅 배열) 배열이 최선의 선택.

리스트List (ArrayList)

Java의 ArrayList는 내부적으로 배열을 사용하되, 용량이 부족하면 자동으로 1.5배 확장하여 크기 제약 없이 사용할 수 있게 만든 동적 배열이다. List 인터페이스를 구현하며 제네릭을 지원한다.

접근(get) O(1)
끝에 추가 O(1) 상각
중간 삽입/삭제 O(n)
List list = new ArrayList<>();
list.add(10); list.add(20);
list.add(1, 15);           // 인덱스 1에 삽입 — 뒤 원소 shift, O(n)
list.remove(Integer.valueOf(20)); // 값으로 제거 (인덱스로 제거하려면 remove(int)와 오버로딩 주의)
Collections.sort(list);
list.sort((a, b) -> b - a); // 내림차순 정렬
주의: list.remove(20)은 인덱스 20을 제거하지만 list.remove(Integer.valueOf(20))은 값 20을 제거한다 — 오토박싱 오버로딩 함정.
활용: 크기가 가변적이고 요소 순서가 중요한 대부분의 상황(입력 저장, 그래프 인접 리스트의 각 노드 리스트).

연결 리스트LinkedList

각 노드가 데이터와 다음(및 이전) 노드에 대한 참조(포인터)를 가지는 자료구조. 메모리가 비연속적으로 흩어져 있어 인덱스 접근은 느리지만, 노드 자체를 알고 있다면 삽입/삭제가 O(1)이다. Java의 LinkedList는 이중 연결 리스트(Doubly Linked List)로 구현되어 Deque 인터페이스도 구현한다.

접근 O(n)
앞/뒤 삽입·삭제 O(1)
중간 삽입(노드 참조 有) O(1)

직접 구현 — 단일 연결 리스트

class Node {
    int data;
    Node next;
    Node(int data) { this.data = data; }
}

class SinglyLinkedList {
    Node head;

    void addFirst(int data) {
        Node newNode = new Node(data);
        newNode.next = head;
        head = newNode;
    }

    void addLast(int data) {
        Node newNode = new Node(data);
        if (head == null) { head = newNode; return; }
        Node cur = head;
        while (cur.next != null) cur = cur.next;
        cur.next = newNode;
    }

    // 재귀로 리스트 역순 뒤집기 — 연결 리스트 단골 문제
    Node reverse(Node node) {
        if (node == null || node.next == null) return node;
        Node newHead = reverse(node.next);
        node.next.next = node;
        node.next = null;
        return newHead;
    }
}
활용: 삽입/삭제가 빈번하고 인덱스 접근이 적은 경우(LRU 캐시 구현, 다항식 표현). 코딩테스트보다 CS 개념(포인터 조작) 이해 목적으로 자주 출제된다.

맵Map (HashMap / TreeMap)

키(Key)-값(Value) 쌍을 저장하는 자료구조. HashMap은 해시 함수로 버킷 인덱스를 계산해 평균 O(1) 접근을 제공하고, TreeMap은 레드-블랙 트리 기반으로 키를 정렬된 상태로 유지하며 O(log n) 접근을 제공한다.

HashMap 조회 평균 O(1)
HashMap 최악 O(n)
TreeMap 조회 O(log n)
Map hm = new HashMap<>();
hm.put("apple", 3);
hm.merge("apple", 1, Integer::sum);       // 존재하면 누적, 없으면 초기값
hm.getOrDefault("banana", 0);
hm.computeIfAbsent("cherry", k -> 0);

TreeMap tm = new TreeMap<>();
tm.put(5, "five"); tm.put(1, "one");
tm.firstKey(); tm.lastKey();
tm.ceilingKey(3);   // 3 이상인 가장 작은 키 — O(log n)
tm.floorKey(3);     // 3 이하인 가장 큰 키
선택 기준: 순서가 필요 없고 최고 속도가 필요하면 HashMap, 정렬 순회·범위 검색(ceiling/floor)이 필요하면 TreeMap.
활용: 빈도수 계산(문자 빈도, 투 포인터와 결합한 부분합), 캐싱/메모이제이션(DP), 그래프의 방문 여부 기록.

세트Set (HashSet / TreeSet)

중복을 허용하지 않는 원소들의 집합. 내부적으로 HashMap/TreeMap을 그대로 재사용해 구현되어 있다(값만 저장, 키만 사용). 원소의 존재 여부 확인에 최적화되어 있다.

Set hs = new HashSet<>();
hs.add(1); hs.add(2); hs.add(1);   // 중복 무시 → size == 2
hs.contains(2);                     // O(1) 평균

TreeSet ts = new TreeSet<>(Arrays.asList(5, 1, 3));
ts.higher(3);  // 3보다 큰 값 중 최소 — O(log n)
ts.lower(3);   // 3보다 작은 값 중 최대
ts.pollFirst(); // 최소값 꺼내며 제거
활용: 중복 제거, 방문 처리(BFS/DFS visited), 두 집합의 교집합·합집합·차집합 연산(retainAll/addAll/removeAll).

스택Stack (LIFO)

Last-In-First-Out — 나중에 넣은 원소가 먼저 나오는 자료구조. Java의 Stack 클래스는 legacy(동기화 오버헤드)이므로, 실전에서는 Deque(ArrayDeque)를 스택처럼 사용하는 것이 권장된다.

push/pop/peek 모두 O(1)
Deque stack = new ArrayDeque<>();
stack.push(1); stack.push(2);
stack.pop();   // 2 반환 후 제거
stack.peek();  // 1 (제거하지 않고 확인)

// 활용 예: 괄호 유효성 검사
boolean isValid(String s) {
    Deque st = new ArrayDeque<>();
    Map pair = Map.of(')', '(', ']', '[', '}', '{');
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') st.push(c);
        else {
            if (st.isEmpty() || st.pop() != pair.get(c)) return false;
        }
    }
    return st.isEmpty();
}
활용: 괄호 매칭, 계산기(중위→후위 변환), 함수 호출 스택 시뮬레이션(재귀 → 반복 변환), DFS의 반복문 구현, 모노토닉 스택(다음 큰 원소 찾기).

큐Queue (FIFO)

First-In-First-Out — 먼저 넣은 원소가 먼저 나오는 자료구조. LinkedList 또는 ArrayDeque로 구현하며, ArrayDeque가 배열 기반이라 더 빠르다.

offer/poll/peek 모두 O(1)
Queue queue = new ArrayDeque<>();
queue.offer(1); queue.offer(2);
queue.poll();  // 1 반환 후 제거
queue.peek();  // 2 (확인만)

// 우선순위 큐(PriorityQueue) — 힙 기반, O(log n) 삽입/삭제
PriorityQueue pq = new PriorityQueue<>();          // 최소 힙 (기본)
PriorityQueue maxPq = new PriorityQueue<>(Collections.reverseOrder()); // 최대 힙

덱Deque (Double-Ended Queue)

양쪽 끝에서 모두 삽입/삭제가 O(1)인 자료구조. Java의 ArrayDeque는 원형 배열(circular array)로 구현되어 Stack과 Queue를 모두 대체할 수 있는 만능 자료구조다.

Deque dq = new ArrayDeque<>();
dq.addFirst(1); dq.addLast(2);
dq.pollFirst(); dq.pollLast();
dq.offerFirst(3); dq.offerLast(4);

// 활용 예: 슬라이딩 윈도우 최댓값 — 단조 감소 덱(Monotonic Deque), O(n)
int[] slidingWindowMax(int[] nums, int k) {
    Deque dq2 = new ArrayDeque<>(); // 인덱스 저장, 값이 감소하는 순서 유지
    int[] result = new int[nums.length - k + 1];
    for (int i = 0; i < nums.length; i++) {
        while (!dq2.isEmpty() && dq2.peekFirst() <= i - k) dq2.pollFirst(); // 윈도우 벗어난 인덱스 제거
        while (!dq2.isEmpty() && nums[dq2.peekLast()] < nums[i]) dq2.pollLast(); // 자신보다 작은 값 제거
        dq2.offerLast(i);
        if (i >= k - 1) result[i - k + 1] = nums[dq2.peekFirst()];
    }
    return result;
}
활용: 슬라이딩 윈도우 최대/최소값(단조 덱), 팰린드롬 검사, BFS 0-1 (가중치 0/1 최단경로에서 덱으로 다익스트라 대체).

트리Tree

노드와 간선으로 이루어진 비선형 계층 자료구조. 사이클이 없는 연결 그래프의 특수한 형태(간선 수 = 노드 수 - 1)로 볼 수 있다. 이진 트리, 이진 탐색 트리(BST), 균형 트리(AVL, Red-Black), 힙(Heap) 등 다양한 변형이 있다.

이진 탐색 트리(BST) 직접 구현

class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int val) { this.val = val; }
}

class BST {
    TreeNode root;

    void insert(int val) { root = insertRec(root, val); }
    TreeNode insertRec(TreeNode node, int val) {
        if (node == null) return new TreeNode(val);
        if (val < node.val) node.left = insertRec(node.left, val);
        else if (val > node.val) node.right = insertRec(node.right, val);
        return node;
    }

    boolean search(TreeNode node, int val) {
        if (node == null) return false;
        if (node.val == val) return true;
        return val < node.val ? search(node.left, val) : search(node.right, val);
    }

    // 중위 순회 — BST에서는 항상 오름차순 결과
    void inorder(TreeNode node, List result) {
        if (node == null) return;
        inorder(node.left, result);
        result.add(node.val);
        inorder(node.right, result);
    }
}
균형 BST 탐색/삽입 O(log n)
편향 BST 최악 O(n)
주의: 정렬된 데이터를 순서대로 삽입하면 BST가 연결 리스트처럼 편향되어 O(n)으로 성능이 저하된다 — 실전에서는 자동 균형을 보장하는 TreeMap/TreeSet을 사용한다.
활용: 계층 구조 표현(파일 시스템, 조직도), 힙 기반 우선순위 큐, 세그먼트/펜윅 트리(구간 질의), 트라이(문자열 검색), LCA(최소 공통 조상).

03 수학 (Number Theory)

소수 & 에라토스테네스의 체Prime Number / Sieve of Eratosthenes

소수는 1과 자기 자신 외의 약수를 갖지 않는 2 이상의 자연수다. 단일 숫자의 소수 판별은 O(√n)로 충분하지만, 특정 범위 내 모든 소수를 구해야 할 때는 에라토스테네스의 체를 사용해 O(n log log n)에 처리한다.

단일 수 소수 판별 — O(√n)

boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; (long) i * i <= n; i++) {   // i*i <= n 까지만 검사하면 충분
        if (n % i == 0) return false;
    }
    return true;
}

에라토스테네스의 체 — O(n log log n)

boolean[] sieve(int n) {
    boolean[] isComposite = new boolean[n + 1]; // true면 합성수
    for (int i = 2; (long) i * i <= n; i++) {
        if (!isComposite[i]) {
            for (int j = i * i; j <= n; j += i) { // i*i부터 시작 — 그 이전 배수는 이미 처리됨
                isComposite[j] = true;
            }
        }
    }
    return isComposite; // isComposite[i]==false && i>=2 → i는 소수
}
단건 판별 O(√n)
범위 전체 O(n log log n)
활용: 소수 리스트 사전 계산 후 여러 쿼리 처리, 소인수분해(체 계산 시 최소소인수 배열도 함께 구성 가능), 골드바흐 추측류 문제.

최대공약수·최소공배수GCD / LCM — Euclidean Algorithm

유클리드 호제법은 두 수의 최대공약수(GCD)를 구하는 알고리즘으로, "두 수 a, b(a>b)의 GCD는 b와 (a mod b)의 GCD와 같다"는 성질을 반복 적용한다. 최소공배수(LCM)는 GCD를 이용해 a*b/GCD(a,b)로 즉시 구한다.

long gcd(long a, long b) {
    return b == 0 ? a : gcd(b, a % b);   // 재귀 유클리드 호제법 — O(log(min(a,b)))
}

long lcm(long a, long b) {
    return a / gcd(a, b) * b;   // 오버플로 방지 위해 나눗셈을 먼저 수행
}

// 반복문 버전 (스택 오버플로 방지)
long gcdIter(long a, long b) {
    while (b != 0) {
        long t = b;
        b = a % b;
        a = t;
    }
    return a;
}
O(log(min(a,b)))
활용: 분수 약분, 주기 계산(톱니바퀴 문제), 여러 수의 공배수/공약수 문제, 확장 유클리드 호제법으로 모듈러 역원 계산(RSA 등).

기하학Geometry — Vector, Convex-Hull

좌표평면 상의 점·선분·다각형 문제를 다루는 분야. 핵심은 두 벡터의 외적(CCW, Counter-ClockWise)으로 세 점의 회전 방향(시계/반시계/일직선)을 판별하는 것이며, 이를 기반으로 볼록 껍질(Convex Hull), 선분 교차 판정 등을 구현한다.

CCW (외적을 이용한 방향 판정)

// 세 점 p1, p2, p3의 방향: 양수=반시계, 음수=시계, 0=일직선
long ccw(int[] p1, int[] p2, int[] p3) {
    long v = (long)(p2[0] - p1[0]) * (p3[1] - p1[1])
           - (long)(p2[1] - p1[1]) * (p3[0] - p1[0]);
    return v;
}

Convex Hull — Graham Scan, O(n log n)

List convexHull(int[][] points) {
    Arrays.sort(points, (a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]); // x, y 기준 정렬
    int n = points.length;
    int[][] hull = new int[2 * n][];
    int k = 0;

    // 아래쪽 껍질
    for (int[] p : points) {
        while (k >= 2 && ccw(hull[k-2], hull[k-1], p) <= 0) k--;
        hull[k++] = p;
    }
    // 위쪽 껍질
    int lower = k + 1;
    for (int i = n - 2; i >= 0; i--) {
        int[] p = points[i];
        while (k >= lower && ccw(hull[k-2], hull[k-1], p) <= 0) k--;
        hull[k++] = p;
    }
    return new ArrayList<>(Arrays.asList(hull).subList(0, k - 1));
}
CCW 판정 O(1)
Convex Hull O(n log n)
활용: 선분 교차 판정(CCW 부호 조합), 다각형 내부 점 판정, 최소 넓이로 모든 점을 감싸는 울타리 문제, GIS/충돌 검출.

04 구현 (Implementation)

DFS-BFSDepth-First Search / Breadth-First Search

그래프·트리를 탐색하는 두 가지 기본 방법. DFS(깊이 우선 탐색)는 한 방향으로 갈 수 있는 만큼 깊이 들어간 뒤 되돌아오며(재귀 또는 스택), BFS(너비 우선 탐색)는 가까운 노드부터 레벨 단위로 탐색한다(큐 사용). BFS는 가중치 없는 그래프에서 최단 거리를 보장한다는 점이 핵심이다.

DFS — 재귀 구현

void dfs(int node, List> graph, boolean[] visited) {
    visited[node] = true;
    System.out.print(node + " ");
    for (int next : graph.get(node)) {
        if (!visited[next]) dfs(next, graph, visited);
    }
}

BFS — 큐 구현 (최단 거리 동시 계산)

int[] bfs(int start, List> graph, int n) {
    int[] dist = new int[n];
    Arrays.fill(dist, -1);
    dist[start] = 0;
    Queue queue = new ArrayDeque<>();
    queue.offer(start);

    while (!queue.isEmpty()) {
        int cur = queue.poll();
        for (int next : graph.get(cur)) {
            if (dist[next] == -1) {           // 미방문 = 아직 최단거리 미확정
                dist[next] = dist[cur] + 1;
                queue.offer(next);
            }
        }
    }
    return dist;
}
DFS/BFS 모두 O(V+E)
선택 기준: 모든 경로를 탐색하거나 사이클을 찾아야 하면 DFS, 최단 거리(가중치 없음)나 레벨별 처리가 필요하면 BFS.
활용: 섬 개수 세기, 미로 최단거리, 연결 요소 찾기, 이분 그래프 판정, 위상 정렬(DFS 기반).

브루트 포스Brute Force

가능한 모든 경우의 수를 전부 탐색해 답을 찾는 방법. 구현이 단순하고 정답을 보장하지만 시간복잡도가 크므로, 입력 크기가 작을 때(N≤20 내외)만 실전에서 사용 가능하다. 문제 설계 시 "일단 완전탐색으로 접근 가능한지" 확인하는 것이 첫 단계다.

// 예: N개 중 최댓값을 만드는 부분집합 찾기 — 2^N 완전탐색
int bruteForceMaxSubset(int[] arr) {
    int n = arr.length, best = Integer.MIN_VALUE;
    for (int mask = 0; mask < (1 << n); mask++) {   // 모든 부분집합 = 2^n 가지
        int sum = 0;
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) != 0) sum += arr[i];
        }
        // 조건 검사 후 최적값 갱신
        best = Math.max(best, sum);
    }
    return best;
}
경우의 수에 비례 — 보통 O(2ⁿ) 또는 O(n!)
활용: N≤15 부분집합 문제, N≤10 순열 문제, 시뮬레이션 문제의 초기 접근, 최적화 전 정답 검증용 코드.

백트래킹Backtracking

완전탐색을 하되, 현재까지의 선택이 답이 될 가능성이 없다고 판단되면 그 즉시 탐색을 중단하고 이전 상태로 되돌아가는(가지치기, Pruning) 방식이다. 트리 형태의 탐색 공간에서 유망하지 않은 가지를 쳐냄으로써 브루트 포스보다 훨씬 빠르게 동작한다.

Java 코드 예시 — N-Queen

class NQueen {
    int n, count = 0;
    int[] col; // col[row] = 해당 row에 놓인 queen의 열 위치

    void solve(int n) {
        this.n = n;
        col = new int[n];
        backtrack(0);
    }

    void backtrack(int row) {
        if (row == n) { count++; return; }   // 종료 조건: 모든 행 배치 완료

        for (int c = 0; c < n; c++) {
            if (isValid(row, c)) {
                col[row] = c;      // 선택
                backtrack(row + 1); // 탐색
                // col[row]는 다음 반복에서 덮어써지므로 별도 되돌리기 불필요
            }
        }
    }

    boolean isValid(int row, int c) {
        for (int r = 0; r < row; r++) {
            // 같은 열이거나 대각선이면 유효하지 않음 → 즉시 가지치기
            if (col[r] == c || Math.abs(col[r] - c) == row - r) return false;
        }
        return true;
    }
}
최악 O(n!) — 가지치기로 실제 탐색량은 대폭 감소
백트래킹의 3요소: ① 선택(Choose) — 후보를 상태에 반영, ② 탐색(Explore) — 다음 단계 재귀 호출, ③ 되돌리기(Un-choose) — 실패 시 상태 복구 후 다음 후보 시도.
활용: N-Queen, 스도쿠, 순열/조합 생성, 부분집합 합 문제, 조합 최적화(TSP 브랜치 앤 바운드).

05 알고리즘 (Algorithm)

슬라이드 윈도우Sliding Window

고정되거나 가변적인 크기의 구간(윈도우)을 배열 위에서 이동시키며 구간 정보를 O(1)에 갱신하는 기법. 매번 구간 합/조건을 처음부터 다시 계산하지 않고, 윈도우가 이동할 때 빠지는 원소를 빼고 들어오는 원소만 더하는 방식으로 O(n²)를 O(n)으로 줄인다.

// 고정 크기 k 윈도우의 최대 합
int maxSumFixedWindow(int[] arr, int k) {
    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += arr[i];
    int maxSum = windowSum;
    for (int i = k; i < arr.length; i++) {
        windowSum += arr[i] - arr[i - k];  // 들어오는 값 더하고 나가는 값 빼기 — O(1)
        maxSum = Math.max(maxSum, windowSum);
    }
    return maxSum;
}

// 가변 크기 윈도우 — 합이 target 이상이 되는 최소 길이 부분배열
int minSubArrayLen(int target, int[] arr) {
    int left = 0, sum = 0, minLen = Integer.MAX_VALUE;
    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];
        while (sum >= target) {           // 조건 만족 시 왼쪽을 최대한 좁힘
            minLen = Math.min(minLen, right - left + 1);
            sum -= arr[left++];
        }
    }
    return minLen == Integer.MAX_VALUE ? 0 : minLen;
}
O(n) — 각 원소가 최대 한 번씩만 들어오고 나감
활용: 최대/최소 부분배열 합, 특정 조건을 만족하는 최소/최대 길이 구간, 문자열 내 특정 패턴을 포함하는 최소 윈도우.

이분 탐색Binary Search

정렬된 배열에서 탐색 범위를 절반씩 줄여가며 목표 값을 찾는 알고리즘. 단순 값 탐색뿐 아니라, "조건을 만족하는 최소/최대값"을 찾는 파라메트릭 서치(Parametric Search)로도 널리 활용된다.

// 기본 이분 탐색
int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;   // (lo+hi)/2는 오버플로 위험 — 이렇게 계산
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

// 파라메트릭 서치: 절단기로 자른 나무 길이의 합이 target 이상이 되는 최대 높이 H 찾기
long parametricSearch(int[] trees, long target) {
    long lo = 0, hi = Arrays.stream(trees).max().getAsInt();
    long answer = 0;
    while (lo <= hi) {
        long mid = lo + (hi - lo) / 2;
        long sum = 0;
        for (int t : trees) if (t > mid) sum += t - mid;

        if (sum >= target) {       // 조건 만족 → 더 큰 높이도 가능한지 탐색
            answer = mid;
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return answer;
}
O(log n)
파라메트릭 서치 O(log(범위) × 검증비용)
적용 신호: "정답이 단조성(monotonic)을 갖는가?" — 어떤 값 X가 조건을 만족하면 X보다 크거나 작은 모든 값도 만족/불만족한다면 파라메트릭 서치를 적용할 수 있다.
활용: Java 내장 Arrays.binarySearch, Collections.binarySearch, 최적 값 탐색(랜선 자르기, 공유기 설치, 배달 시간).

투 포인터Two Pointer

두 개의 인덱스(포인터)를 배열의 양 끝 또는 같은 방향으로 움직이며 조건을 만족하는 구간/쌍을 O(n)에 찾는 기법. 정렬된 배열에서 특히 강력하다.

// 정렬된 배열에서 합이 target인 두 수 찾기 — O(n)
int[] twoSumSorted(int[] arr, int target) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int sum = arr[left] + arr[right];
        if (sum == target) return new int[]{left, right};
        else if (sum < target) left++;   // 합이 작으면 왼쪽을 오른쪽으로 이동해 합 증가
        else right--;                     // 합이 크면 오른쪽을 왼쪽으로 이동해 합 감소
    }
    return new int[]{-1, -1};
}
O(n) (정렬 필요 시 O(n log n) 추가)
활용: 정렬 배열에서 쌍/삼중 합 찾기(3Sum), 팰린드롬 검사, 두 정렬 리스트 병합, 슬라이딩 윈도우와 결합한 부분 배열 문제.

탐욕 알고리즘Greedy Algorithm

매 순간 현재 상황에서 가장 좋아 보이는 선택을 반복해 전체 최적해를 구하려는 방법. 항상 최적해를 보장하지는 않으며, 문제가 탐욕적 선택 속성(Greedy Choice Property)과 최적 부분구조(Optimal Substructure)를 만족할 때만 유효하다 — 적용 전 반드시 수학적 근거(교환 논증 등)로 정당성을 확인해야 한다.

// 회의실 배정 — 종료시간 기준 정렬 후 탐욕 선택, 정당성: 가장 먼저 끝나는 회의를 선택하는 것이 항상 최적
int maxMeetings(int[][] meetings) {
    Arrays.sort(meetings, (a, b) -> a[1] - b[1]);  // 종료시간 오름차순 정렬
    int count = 0, lastEnd = 0;
    for (int[] m : meetings) {
        if (m[0] >= lastEnd) {   // 이전 회의가 끝난 후 시작 가능하면 선택
            count++;
            lastEnd = m[1];
        }
    }
    return count;
}

// 거스름돈 — 동전 단위가 배수 관계일 때만 탐욕이 최적 (아닐 경우 DP 필요)
int minCoins(int[] coins, int amount) {
    Arrays.sort(coins);
    int count = 0;
    for (int i = coins.length - 1; i >= 0 && amount > 0; i--) {
        count += amount / coins[i];
        amount %= coins[i];
    }
    return amount == 0 ? count : -1;
}
주의: 동전 단위가 {1, 3, 4}처럼 배수 관계가 아니면 탐욕이 최적해를 보장하지 못한다(6원을 4+1+1이 아닌 3+3으로 만들어야 최소 개수). 이런 경우 DP로 전환해야 한다.
활용: 활동 선택 문제, 최소 신장 트리(Kruskal/Prim), 허프만 코딩, 다익스트라 최단경로.

재귀 함수 작성 방법Writing Recursive Function

함수가 자기 자신을 호출하는 기법. 반드시 ① 종료 조건(Base Case)과 ② 문제를 더 작은 단위로 줄이는 점화 관계(Recursive Case) 두 가지를 정의해야 무한 재귀를 피할 수 있다. 내부적으로 함수 호출 스택을 사용하므로 깊이가 깊으면 StackOverflowError가 발생할 수 있다(Java 기본 스택 깊이는 대략 1만 회 내외).

// 팩토리얼 — 가장 기본적인 재귀 구조
long factorial(int n) {
    if (n <= 1) return 1;              // ① 종료 조건
    return n * factorial(n - 1);        // ② 더 작은 문제로 축소
}

// 피보나치 — 메모이제이션 없이는 O(2^n), 있으면 O(n)
Map memo = new HashMap<>();
long fibonacci(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);  // 이미 계산한 값 재사용 (top-down DP)
    long result = fibonacci(n - 1) + fibonacci(n - 2);
    memo.put(n, result);
    return result;
}
재귀 설계 3단계: ① 가장 작은 경우(n=0, n=1)를 손으로 풀어 종료조건을 정한다. ② "이 문제가 더 작은 동일한 문제로 어떻게 줄어드는가"를 점화식으로 세운다. ③ 중복 계산이 생기면 메모이제이션을 추가한다.
활용: 트리/그래프 순회, 분할 정복, DP의 top-down 구현, 백트래킹.

정렬Sorting

원소들을 특정 순서(오름차순/내림차순)로 재배열하는 알고리즘. Java의 Arrays.sort()는 원시타입에는 듀얼 피벗 퀵정렬(O(n log n) 평균), 객체타입에는 팀소트(TimSort, 안정 정렬)를 사용한다.

병합 정렬 — 분할 정복 기반, O(n log n) 항상 보장

void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = (left + right) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
}

void merge(int[] arr, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right) {
        temp[k++] = (arr[i] <= arr[j]) ? arr[i++] : arr[j++];  // <= 사용 시 안정 정렬 유지
    }
    while (i <= mid) temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];
    System.arraycopy(temp, 0, arr, left, temp.length);
}

퀵 정렬 — 평균 O(n log n), 최악 O(n²)

void quickSort(int[] arr, int lo, int hi) {
    if (lo >= hi) return;
    int pivotIdx = partition(arr, lo, hi);
    quickSort(arr, lo, pivotIdx - 1);
    quickSort(arr, pivotIdx + 1, hi);
}

int partition(int[] arr, int lo, int hi) {
    int pivot = arr[hi];
    int i = lo - 1;
    for (int j = lo; j < hi; j++) {
        if (arr[j] < pivot) {
            i++;
            int t = arr[i]; arr[i] = arr[j]; arr[j] = t;
        }
    }
    int t = arr[i + 1]; arr[i + 1] = arr[hi]; arr[hi] = t;
    return i + 1;
}

분할 정복Divide and Conquer

문제를 ① 분할(Divide) — 더 작은 동일 유형의 부분 문제로 나누고, ② 정복(Conquer) — 각 부분 문제를 재귀적으로 해결한 뒤, ③ 결합(Combine) — 부분 해를 합쳐 전체 해를 구하는 전략. 병합정렬, 퀵정렬, 이분탐색, 거듭제곱 빠른 계산 등이 대표적이다.

// 분할 정복을 이용한 빠른 거듭제곱 — O(log n), 일반 반복곱은 O(n)
long power(long base, long exp, long mod) {
    if (exp == 0) return 1;
    long half = power(base, exp / 2, mod);
    long result = (half * half) % mod;
    if (exp % 2 == 1) result = (result * base) % mod;  // 지수가 홀수면 base 한 번 더 곱함
    return result;
}

// 최대/최소 동시 탐색 — 분할정복으로 비교 횟수 절감
int[] findMinMax(int[] arr, int lo, int hi) {
    if (lo == hi) return new int[]{arr[lo], arr[lo]};
    int mid = (lo + hi) / 2;
    int[] left = findMinMax(arr, lo, mid);
    int[] right = findMinMax(arr, mid + 1, hi);
    return new int[]{Math.min(left[0], right[0]), Math.max(left[1], right[1])};
}
활용: 거듭제곱/행렬 거듭제곱(피보나치 O(log n) 계산), 최근접 점의 쌍(Closest Pair), 큰 수의 곱셈(Karatsuba).

문자열 검색 알고리즘 — KMPKnuth-Morris-Pratt

패턴 매칭 시 일치하지 않는 지점에서 이미 비교했던 정보를 버리지 않고 다음 비교 시작 위치를 건너뛰어, 단순 매칭(O(nm))을 O(n+m)으로 줄이는 알고리즘. 핵심은 패턴 자기 자신 내부의 접두사=접미사(prefix=suffix) 최대 길이를 미리 계산해두는 실패 함수(failure function, pi 배열)다.

// 실패 함수(pi 배열) 계산 — pattern[0..i]에서 접두사=접미사인 최대 길이
int[] getFailure(String pattern) {
    int m = pattern.length();
    int[] pi = new int[m];
    int j = 0;
    for (int i = 1; i < m; i++) {
        while (j > 0 && pattern.charAt(i) != pattern.charAt(j)) {
            j = pi[j - 1];       // 불일치 시 이전 접두사 길이로 되돌아감 (핵심)
        }
        if (pattern.charAt(i) == pattern.charAt(j)) {
            pi[i] = ++j;
        }
    }
    return pi;
}

// KMP 매칭 — O(n + m)
List kmpSearch(String text, String pattern) {
    List result = new ArrayList<>();
    int[] pi = getFailure(pattern);
    int j = 0;
    for (int i = 0; i < text.length(); i++) {
        while (j > 0 && text.charAt(i) != pattern.charAt(j)) {
            j = pi[j - 1];
        }
        if (text.charAt(i) == pattern.charAt(j)) {
            if (j == pattern.length() - 1) {
                result.add(i - j);   // 매칭 성공 위치 기록
                j = pi[j];
            } else j++;
        }
    }
    return result;
}
전처리 O(m)
탐색 O(n)
전체 O(n+m)
활용: 긴 텍스트에서 패턴 반복 탐색, DNA 서열 매칭, 문자열 주기성 판별(pi 배열의 성질 이용).

트라이Trie (Prefix Tree)

문자열 집합을 저장하는 트리 자료구조로, 루트에서 특정 노드까지의 경로가 하나의 문자열(접두사)을 나타낸다. 공통 접두사를 공유하는 노드를 재사용해 문자열 길이에 비례하는 O(L) 시간에 삽입/검색이 가능하다.

class TrieNode {
    Map children = new HashMap<>();
    boolean isEnd = false;
}

class Trie {
    TrieNode root = new TrieNode();

    void insert(String word) {
        TrieNode node = root;
        for (char c : word.toCharArray()) {
            node = node.children.computeIfAbsent(c, k -> new TrieNode());
        }
        node.isEnd = true;
    }

    boolean search(String word) {
        TrieNode node = find(word);
        return node != null && node.isEnd;
    }

    boolean startsWith(String prefix) {
        return find(prefix) != null;
    }

    private TrieNode find(String s) {
        TrieNode node = root;
        for (char c : s.toCharArray()) {
            node = node.children.get(c);
            if (node == null) return null;
        }
        return node;
    }
}
삽입/검색 O(L) (L=문자열 길이)
공간 O(전체 문자 수 × 알파벳 크기)
활용: 자동완성, 사전 검색, IP 라우팅(최장 접두사 매칭), 문자열 집합에서 특정 접두사를 가진 단어 개수 세기.

유니온-파인드Union-Find (Disjoint Set Union)

서로소 집합(disjoint set)들을 관리하며, 두 원소가 같은 집합에 속하는지(Find)와 두 집합을 합치는(Union) 연산을 빠르게 처리하는 자료구조. 경로 압축(Path Compression)과 랭크에 의한 합치기(Union by Rank)를 함께 적용하면 사실상 상수 시간(O(α(n)), 아커만 역함수)에 가까워진다.

class UnionFind {
    int[] parent, rank;

    UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;   // 초기에는 각자가 자기 자신의 대표
    }

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);   // 경로 압축: 탐색하며 지나온 노드를 루트에 직접 연결
        }
        return parent[x];
    }

    void union(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX == rootY) return;         // 이미 같은 집합 — 사이클 발생 지점

        // 랭크(트리 높이)가 낮은 쪽을 높은 쪽 밑에 붙여 트리가 편향되지 않게 함
        if (rank[rootX] < rank[rootY]) parent[rootX] = rootY;
        else if (rank[rootX] > rank[rootY]) parent[rootY] = rootX;
        else { parent[rootY] = rootX; rank[rootX]++; }
    }

    boolean isConnected(int x, int y) { return find(x) == find(y); }
}
경로압축+랭크 적용 시 사실상 O(1) (엄밀히 O(α(n)))
활용: 크루스칼 MST(사이클 판정), 네트워크 연결성 확인, 친구 관계 그룹핑, 이미지의 연결 요소 찾기.

06 조합-순열 (Combination-Permutation)

NextPerm / PrevPermNext Permutation / Previous Permutation

현재 순열을 사전순 기준으로 바로 다음(또는 이전) 순열로 바꾸는 알고리즘. 모든 순열을 저장하지 않고도 O(n)에 in-place로 다음 순열을 생성할 수 있어, 순열을 사전순으로 하나씩 순회할 때 매우 효율적이다.

// 다음 순열 — Java Collections에는 없어 직접 구현 (C++의 next_permutation과 동일 로직)
boolean nextPermutation(int[] arr) {
    int n = arr.length;
    int i = n - 2;
    // 1) 뒤에서부터 증가가 꺾이는 지점 i를 찾는다 (arr[i] < arr[i+1])
    while (i >= 0 && arr[i] >= arr[i + 1]) i--;
    if (i < 0) { reverse(arr, 0, n - 1); return false; } // 이미 마지막 순열 → 첫 순열로 순환

    // 2) i보다 큰 값들 중 가장 작은 값을 뒤에서 찾아 swap
    int j = n - 1;
    while (arr[j] <= arr[i]) j--;
    swap(arr, i, j);

    // 3) i 이후 구간을 오름차순(가장 작은 배열)으로 뒤집는다
    reverse(arr, i + 1, n - 1);
    return true;
}

void reverse(int[] arr, int lo, int hi) {
    while (lo < hi) swap(arr, lo++, hi--);
}
void swap(int[] arr, int i, int j) { int t = arr[i]; arr[i] = arr[j]; arr[j] = t; }
O(n) per call
활용: 사전순 K번째 순열 찾기, 모든 순열을 메모리 효율적으로 순회, 순열 관련 완전탐색 문제.

부분집합Subset / PowerSet, BitSubset

N개 원소로 이루어진 집합은 총 2ᴺ개의 부분집합(공집합, 전체집합 포함)을 가진다. 각 원소를 "포함/미포함" 두 가지 상태로 볼 수 있으므로, 0부터 2ᴺ-1까지의 정수를 비트마스크로 사용하면 모든 부분집합을 표현할 수 있다.

List> allSubsets(int[] arr) {
    int n = arr.length;
    List> result = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {   // mask의 각 비트가 해당 원소의 포함 여부
        List subset = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) != 0) subset.add(arr[i]);
        }
        result.add(subset);
    }
    return result;
}

// 재귀(백트래킹)로 부분집합 생성 — 트리 순회 관점에서 이해
void backtrackSubset(int[] arr, int idx, List cur, List> result) {
    if (idx == arr.length) { result.add(new ArrayList<>(cur)); return; }
    backtrackSubset(arr, idx + 1, cur, result);        // 현재 원소 미포함
    cur.add(arr[idx]);
    backtrackSubset(arr, idx + 1, cur, result);        // 현재 원소 포함
    cur.remove(cur.size() - 1);
}
O(2ⁿ × n)
활용: 부분집합 합 문제, 비트마스크 DP(외판원 문제), 최적 조합 완전탐색(N≤20).

조합Combination

N개 중 순서 없이 R개를 뽑는 경우의 수(nCr). 백트래킹으로 "시작 인덱스 이후"만 재귀 탐색하도록 제한하면 순서가 자연스럽게 배제되어 중복 없이 생성된다.

void combination(int[] arr, int r, int start, List cur, List> result) {
    if (cur.size() == r) { result.add(new ArrayList<>(cur)); return; }
    for (int i = start; i < arr.length; i++) {   // start부터 시작 → 이전 원소를 다시 뽑지 않음(순서 무관 보장)
        cur.add(arr[i]);
        combination(arr, r, i + 1, cur, result);
        cur.remove(cur.size() - 1);
    }
}

// nCr 값 자체가 필요할 때 — 파스칼의 삼각형 (동적계획법)
long[][] pascalTriangle(int n) {
    long[][] C = new long[n + 1][n + 1];
    for (int i = 0; i <= n; i++) {
        C[i][0] = 1;
        for (int j = 1; j <= i; j++) {
            C[i][j] = C[i - 1][j - 1] + C[i - 1][j];   // nCr = (n-1)C(r-1) + (n-1)Cr
        }
    }
    return C;
}
조합 생성 O(nCr × r)
nCr 값 계산(DP) O(n²)
활용: 로또 번호 조합, 팀 구성 경우의 수, DP 점화식에서 조합수 활용(카탈랑 수 등).

중복 조합Combination with Repetition, BitPerm

N개 중 순서 없이, 같은 원소를 여러 번 선택 가능하게 R개를 뽑는 경우의 수(nHr = (n+r-1)Cr). 백트래킹 시 다음 재귀 호출을 i(다음 인덱스가 아닌 자기 자신부터 시작)로 넘겨 같은 원소를 다시 선택할 수 있게 한다.

void combinationWithRepetition(int[] arr, int r, int start, List cur, List> result) {
    if (cur.size() == r) { result.add(new ArrayList<>(cur)); return; }
    for (int i = start; i < arr.length; i++) {
        cur.add(arr[i]);
        combinationWithRepetition(arr, r, i, cur, result);  // i (i+1 아님) — 같은 원소 재선택 허용
        cur.remove(cur.size() - 1);
    }
}
활용: 음료 N종에서 R개 고르기(중복 허용), 자연수 분할 문제, 다중집합(multiset) 관련 완전탐색.

순열Permutation

N개 중 순서를 고려하여 R개를 나열하는 경우의 수(nPr = n!/(n-r)!). 방문 배열(visited)로 이미 사용한 원소를 제외하며 재귀적으로 생성한다.

void permutation(int[] arr, int r, boolean[] visited, List cur, List> result) {
    if (cur.size() == r) { result.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < arr.length; i++) {
        if (visited[i]) continue;          // 순서를 구분하므로 시작 인덱스 제한 없이 전체를 돌되 방문 여부만 체크
        visited[i] = true;
        cur.add(arr[i]);
        permutation(arr, r, visited, cur, result);
        cur.remove(cur.size() - 1);
        visited[i] = false;                // 백트래킹: 다른 경로 탐색 위해 되돌림
    }
}
O(nPr × r)
활용: 순서가 의미 있는 경우의 수(줄 세우기, 경로 방문 순서), 외판원 문제(TSP) 완전탐색 기반, 다음 순열과 결합한 사전순 탐색.

중복 순열Permutation with Repetition

N개 중 순서를 고려하며 중복을 허용해 R개를 나열하는 경우의 수(n^r). 방문 배열 없이 매번 전체 원소를 다시 순회하면 자연스럽게 중복이 허용된다.

void permutationWithRepetition(int[] arr, int r, List cur, List> result) {
    if (cur.size() == r) { result.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < arr.length; i++) {
        cur.add(arr[i]);
        permutationWithRepetition(arr, r, cur, result);   // visited 체크 없음 → 같은 원소 재사용 가능
        cur.remove(cur.size() - 1);
    }
}
O(nʳ × r)
활용: 비밀번호 전수 조사, 주사위를 R번 굴렸을 때 나올 수 있는 모든 경우, 문자열 생성 문제.

07 그래프 (Graph)

그래프 표현 방법Graph Representation — adjM, adjL, userNode

그래프는 크게 인접 행렬(Adjacency Matrix)과 인접 리스트(Adjacency List) 두 가지로 표현한다. 정점 수 대비 간선 수가 많은 밀집 그래프면 행렬이, 간선이 적은 희소 그래프면 리스트가 유리하다. 사용자 정의 노드 클래스(userNode)로 그래프를 표현하면 각 노드에 추가 속성을 담기 용이하다.

최소신장트리Minimum Spanning Tree — Kruskal / Prim

그래프의 모든 정점을 사이클 없이, 최소 비용으로 연결하는 부분 그래프(트리)를 찾는 문제. 크루스칼은 간선을 가중치 순으로 정렬해 사이클을 만들지 않는 간선만 유니온-파인드로 선택하고(간선 중심), 프림은 하나의 정점에서 시작해 우선순위 큐로 매번 가장 싼 인접 간선을 확장한다(정점 중심).

크루스칼 (Kruskal) — 간선 정렬 + Union-Find, O(E log E)

int kruskalMST(int n, int[][] edges) {  // edges[i] = {u, v, weight}
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);   // 가중치 오름차순 정렬
    UnionFind uf = new UnionFind(n);
    int totalCost = 0, edgeCount = 0;

    for (int[] e : edges) {
        int u = e[0], v = e[1], w = e[2];
        if (!uf.isConnected(u, v)) {     // 사이클을 만들지 않는 간선만 채택
            uf.union(u, v);
            totalCost += w;
            edgeCount++;
            if (edgeCount == n - 1) break;   // 트리 완성 (정점 n개면 간선 n-1개)
        }
    }
    return totalCost;
}

프림 (Prim) — 우선순위 큐, O(E log V)

int primMST(int n, List> adjL, int start) {
    boolean[] visited = new boolean[n];
    PriorityQueue pq = new PriorityQueue<>((a, b) -> a[1] - b[1]); // [정점, 가중치] 최소힙
    pq.offer(new int[]{start, 0});
    int totalCost = 0;

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int node = cur[0], cost = cur[1];
        if (visited[node]) continue;      // 이미 트리에 포함된 정점은 스킵
        visited[node] = true;
        totalCost += cost;

        for (int[] next : adjL.get(node)) {
            if (!visited[next[0]]) pq.offer(next);  // 인접한 미방문 정점을 후보로 등록
        }
    }
    return totalCost;
}
Kruskal O(E log E)
Prim O(E log V)
선택 기준: 간선이 적은 희소 그래프면 크루스칼, 정점 수 대비 간선이 매우 많은 밀집 그래프면 프림이 유리한 경향이 있다.
활용: 도로/통신망 최소 비용 연결, 클러스터링(MST 간선을 끊어 그룹 형성).

최단경로Shortest Path — Dijkstra / Bellman-Ford / Floyd-Warshall

세 알고리즘 모두 최단경로를 구하지만 적용 조건이 다르다. 다익스트라는 음수 가중치가 없을 때 한 정점에서 모든 정점까지의 최단거리를, 벨만-포드는 음수 가중치가 있어도(음수 사이클만 없으면) 처리 가능하며 음수 사이클 탐지도 가능하다. 플로이드-워셜은 모든 정점 쌍 간의 최단거리를 한 번에 구한다.

다익스트라 — 우선순위 큐, O((V+E) log V)

int[] dijkstra(int n, List> adjL, int start) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;
    PriorityQueue pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{start, 0});

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int node = cur[0], d = cur[1];
        if (d > dist[node]) continue;    // 이미 더 짧은 경로로 갱신된 적 있으면 스킵 (지연 삭제)

        for (int[] next : adjL.get(node)) {
            int nd = d + next[1];
            if (nd < dist[next[0]]) {    // 완화(Relaxation): 더 짧은 경로 발견 시 갱신
                dist[next[0]] = nd;
                pq.offer(new int[]{next[0], nd});
            }
        }
    }
    return dist;
}

벨만-포드 — 모든 간선을 V-1번 완화, O(VE)

int[] bellmanFord(int n, int[][] edges, int start) {  // edges[i] = {u, v, w}
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;

    for (int i = 0; i < n - 1; i++) {          // 최단경로는 최대 V-1개 간선으로 구성됨
        for (int[] e : edges) {
            if (dist[e[0]] != Integer.MAX_VALUE && dist[e[0]] + e[2] < dist[e[1]]) {
                dist[e[1]] = dist[e[0]] + e[2];
            }
        }
    }

    // V번째 순회에서도 갱신이 일어나면 음수 사이클 존재
    for (int[] e : edges) {
        if (dist[e[0]] != Integer.MAX_VALUE && dist[e[0]] + e[2] < dist[e[1]]) {
            return null;   // 음수 사이클 탐지
        }
    }
    return dist;
}

플로이드-워셜 — 모든 쌍 최단경로, O(V³)

int[][] floydWarshall(int n, int[][] adjM) {  // adjM: 초기 인접행렬 (없으면 INF)
    int[][] dist = adjM.clone();
    for (int k = 0; k < n; k++) {          // 경유지 k를 하나씩 고려
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];  // i→k→j가 i→j보다 짧으면 갱신
                }
            }
        }
    }
    return dist;
}
알고리즘시간복잡도음수 가중치용도
다익스트라O((V+E)log V)불가단일 출발점 최단경로
벨만-포드O(VE)가능(음수사이클 탐지)단일 출발점, 음수 간선 존재 시
플로이드-워셜O(V³)가능(음수사이클 없어야)모든 쌍 최단경로, V≤400 내외
활용: 내비게이션 최단경로, 네트워크 라우팅, 환율 차익거래 탐지(벨만-포드 음수사이클), 도시 간 전체 최단거리 테이블(플로이드-워셜).

Bipartite (이분 그래프)2-Coloring

그래프의 정점을 두 그룹으로 나누어 같은 그룹 내에는 간선이 존재하지 않도록 나눌 수 있는지 판별하는 문제. BFS/DFS로 인접한 정점에 서로 다른 색을 번갈아 칠하다가, 이미 칠해진 인접 정점이 같은 색이면 이분 그래프가 아니다.

boolean isBipartite(int n, List> adjL) {
    int[] color = new int[n];
    Arrays.fill(color, -1);

    for (int i = 0; i < n; i++) {
        if (color[i] != -1) continue;
        color[i] = 0;
        Queue queue = new ArrayDeque<>();
        queue.offer(i);

        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int next : adjL.get(cur)) {
                if (color[next] == -1) {
                    color[next] = 1 - color[cur];   // 인접 정점은 반대 색으로 칠함
                    queue.offer(next);
                } else if (color[next] == color[cur]) {
                    return false;   // 인접한데 같은 색 → 이분 그래프 아님
                }
            }
        }
    }
    return true;
}
O(V+E)
활용: 이분 매칭(작업-일꾼 배정), 홀수 사이클 존재 여부 판별, 그래프 색칠 문제의 특수 케이스.

단절점Articulation Points (Cut Vertices)

그래프에서 제거하면 그래프가 두 개 이상의 연결 요소로 분리되는 정점. DFS 방문 순서(discovery time, disc)와 DFS 트리에서 역방향 간선을 통해 조상으로 갈 수 있는 최소 발견 시각(low)을 비교하는 Tarjan의 알고리즘으로 O(V+E)에 찾는다.

class ArticulationPoints {
    int[] disc, low;
    boolean[] visited, isArticulation;
    int timer = 0;
    List> adjL;

    void findArticulationPoints(int n, List> adjL) {
        this.adjL = adjL;
        disc = new int[n]; low = new int[n];
        visited = new boolean[n]; isArticulation = new boolean[n];
        for (int i = 0; i < n; i++) {
            if (!visited[i]) dfs(i, -1, i == 0 ? 0 : -1);  // 루트는 별도 처리
        }
    }

    void dfs(int u, int parent, int isRoot) {
        visited[u] = true;
        disc[u] = low[u] = timer++;
        int children = 0;

        for (int v : adjL.get(u)) {
            if (v == parent) continue;
            if (visited[v]) {
                low[u] = Math.min(low[u], disc[v]);   // 역방향 간선 — 조상에 접근 가능
            } else {
                children++;
                dfs(v, u, -1);
                low[u] = Math.min(low[u], low[v]);
                // 루트가 아니면서, 자식이 u를 거치지 않고는 조상으로 못 가면 u는 단절점
                if (isRoot != 0 && low[v] >= disc[u]) isArticulation[u] = true;
            }
        }
        // 루트는 자식이 2개 이상일 때만 단절점
        if (isRoot == 0 && children >= 2) isArticulation[u] = true;
    }
}
O(V+E)
활용: 네트워크의 SPOF(단일 장애점) 탐지, 도로망에서 끊기면 마을이 고립되는 지점 찾기.

위상 정렬Topological Sort

방향 비순환 그래프(DAG)에서 모든 간선 u→v에 대해 u가 v보다 먼저 오도록 정점을 일렬로 나열하는 것. 진입차수(in-degree)가 0인 정점부터 큐에 넣고 하나씩 제거하며 인접 정점의 진입차수를 낮추는 칸의 알고리즘(Kahn's Algorithm)이 대표적이다.

List topologicalSort(int n, List> adjL) {
    int[] inDegree = new int[n];
    for (List neighbors : adjL) {
        for (int v : neighbors) inDegree[v]++;   // 각 정점의 진입차수 계산
    }

    Queue queue = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);    // 진입차수 0 = 선행 조건 없음 → 먼저 처리 가능
    }

    List result = new ArrayList<>();
    while (!queue.isEmpty()) {
        int cur = queue.poll();
        result.add(cur);
        for (int next : adjL.get(cur)) {
            if (--inDegree[next] == 0) queue.offer(next);  // 선행 정점 모두 처리되면 큐에 추가
        }
    }

    // 결과 크기가 n보다 작으면 사이클 존재 → 위상 정렬 불가
    return result.size() == n ? result : new ArrayList<>();
}
O(V+E)
활용: 선수과목 이수 순서, 빌드 의존성 처리(Makefile), 작업 스케줄링, DAG 위에서의 DP(가장 긴 경로 등).

최소 공통 조상Lowest Common Ancestor

트리에서 두 노드의 가장 가까운 공통 조상을 찾는 문제. 매 쿼리마다 O(depth)로 찾으면 느리므로, 희소 테이블(Sparse Table)로 각 노드의 2ᵏ번째 조상을 미리 계산해두면 쿼리당 O(log N)에 처리할 수 있다.

class LCA {
    int LOG;
    int[][] parent;   // parent[k][v] = v의 2^k번째 조상
    int[] depth;

    void build(int n, List> adjL, int root) {
        LOG = (int) (Math.log(n) / Math.log(2)) + 1;
        parent = new int[LOG][n];
        depth = new int[n];
        boolean[] visited = new boolean[n];

        // 1) BFS로 depth와 직속 부모(parent[0]) 계산
        Queue queue = new ArrayDeque<>();
        queue.offer(root); visited[root] = true; parent[0][root] = root;
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int next : adjL.get(cur)) {
                if (!visited[next]) {
                    visited[next] = true;
                    depth[next] = depth[cur] + 1;
                    parent[0][next] = cur;
                    queue.offer(next);
                }
            }
        }

        // 2) 점프 테이블 구성 — 2^k번째 조상 = (2^(k-1)번째 조상)의 2^(k-1)번째 조상
        for (int k = 1; k < LOG; k++) {
            for (int v = 0; v < n; v++) {
                parent[k][v] = parent[k - 1][parent[k - 1][v]];
            }
        }
    }

    int lca(int u, int v) {
        if (depth[u] < depth[v]) { int t = u; u = v; v = t; }
        int diff = depth[u] - depth[v];
        for (int k = 0; k < LOG; k++) {                 // 깊이를 먼저 맞춘다
            if (((diff >> k) & 1) == 1) u = parent[k][u];
        }
        if (u == v) return u;
        for (int k = LOG - 1; k >= 0; k--) {             // 큰 점프부터 시도하며 공통조상 직전까지 접근
            if (parent[k][u] != parent[k][v]) { u = parent[k][u]; v = parent[k][v]; }
        }
        return parent[0][u];
    }
}
전처리 O(N log N)
쿼리당 O(log N)
활용: 트리에서 두 노드 간 거리 계산(depth[u]+depth[v]-2×depth[lca]), 조직도 상 공통 상급자 찾기, 트리 경로 쿼리.

세그먼트 트리 / 펜윅 트리Segment Tree / Fenwick Tree (BIT)

배열의 구간 합/최솟값/최댓값 질의와 특정 원소 갱신을 모두 O(log n)에 처리하는 자료구조. 세그먼트 트리는 완전 이진 트리로 임의 구간 연산에 범용적이고, 펜윅 트리(Binary Indexed Tree)는 비트 연산만으로 구현되어 구간 합에 특화되어 있으며 구현이 더 간결하다.

펜윅 트리 (구간 합 특화) — O(log n)

class Fenwick {
    long[] tree;
    int n;

    Fenwick(int n) { this.n = n; tree = new long[n + 1]; }

    void update(int i, long delta) {           // i번째 값에 delta만큼 더하기
        for (; i <= n; i += i & (-i)) {         // i & (-i) = 최하위 비트 — 다음 담당 구간으로 이동
            tree[i] += delta;
        }
    }

    long prefixSum(int i) {                      // 1~i 구간 합
        long sum = 0;
        for (; i > 0; i -= i & (-i)) {
            sum += tree[i];
        }
        return sum;
    }

    long rangeSum(int l, int r) {                 // l~r 구간 합 = prefixSum(r) - prefixSum(l-1)
        return prefixSum(r) - prefixSum(l - 1);
    }
}

세그먼트 트리 (범용 구간 질의) — O(log n)

class SegmentTree {
    long[] tree;
    int n;

    SegmentTree(int[] arr) {
        n = arr.length;
        tree = new long[4 * n];
        build(arr, 1, 0, n - 1);
    }

    void build(int[] arr, int node, int start, int end) {
        if (start == end) { tree[node] = arr[start]; return; }
        int mid = (start + end) / 2;
        build(arr, node * 2, start, mid);
        build(arr, node * 2 + 1, mid + 1, end);
        tree[node] = tree[node * 2] + tree[node * 2 + 1];   // 합 세그먼트 트리 예시 (최소/최대도 동일 구조)
    }

    void update(int node, int start, int end, int idx, int val) {
        if (start == end) { tree[node] = val; return; }
        int mid = (start + end) / 2;
        if (idx <= mid) update(node * 2, start, mid, idx, val);
        else update(node * 2 + 1, mid + 1, end, idx, val);
        tree[node] = tree[node * 2] + tree[node * 2 + 1];
    }

    long query(int node, int start, int end, int l, int r) {
        if (r < start || end < l) return 0;           // 범위 밖 — 영향 없음
        if (l <= start && end <= r) return tree[node]; // 완전 포함 — 바로 반환
        int mid = (start + end) / 2;
        return query(node * 2, start, mid, l, r) + query(node * 2 + 1, mid + 1, end, l, r);
    }
}
구간 합구간 최솟값/최댓값구현 난이도
펜윅 트리매우 간결불가(합 전용 구조)쉬움
세그먼트 트리가능가능(비교 연산만 바꾸면 됨)중간
활용: 구간 합 갱신 쿼리가 반복되는 문제, RMQ(Range Minimum/Maximum Query), 재고 변동 누적 관리, 좌표압축과 결합한 역순 쌍 세기.

08 동적 계획법 (Dynamic Programming)

점화식 & 관계식 유도Top-down Memoization / Bottom-up Tabulation

DP는 중복되는 부분 문제(Overlapping Subproblems)와 최적 부분구조(Optimal Substructure)를 가진 문제를, 작은 문제의 답을 저장해두고 재사용함으로써 지수 시간을 다항 시간으로 줄이는 기법이다. 구현 방식은 두 가지다 — Top-down(메모이제이션)은 재귀 호출을 그대로 쓰되 계산 결과를 캐싱하고, Bottom-up(테이블화)은 작은 인덱스부터 배열을 채워나간다.

점화식 유도 3단계

  1. 상태 정의: "dp[i]가 무엇을 의미하는가"를 명확히 한다 (예: dp[i] = i번째까지 고려했을 때의 최적값).
  2. 점화식 도출: dp[i]를 더 작은 dp[j] (j<i)들의 관계로 표현한다.
  3. 초기값(Base Case) 설정: 더 이상 쪼갤 수 없는 최소 단위의 답을 명시한다.

Java 코드 예시 — 계단 오르기 (Top-down vs Bottom-up)

// 점화식: dp[i] = dp[i-1] + dp[i-2]  (i번째 계단에 도달하는 방법 수 = 한 칸 전 + 두 칸 전)

// Top-down (메모이제이션)
long[] memo;
long climbStairsTopDown(int n) {
    memo = new long[n + 1];
    Arrays.fill(memo, -1);
    return solve(n);
}
long solve(int n) {
    if (n <= 1) return 1;                 // Base Case
    if (memo[n] != -1) return memo[n];    // 이미 계산됨 → 재사용
    return memo[n] = solve(n - 1) + solve(n - 2);
}

// Bottom-up (테이블화) — 재귀 호출 스택 오버헤드 없음, 보통 더 빠름
long climbStairsBottomUp(int n) {
    long[] dp = new long[n + 1];
    dp[0] = 1;
    if (n >= 1) dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}
선택 기준: 점화식을 떠올리기 쉬운 초기 단계에는 Top-down이 직관적이고(재귀 그대로 캐싱만 추가), 최적화·공간 절약(1차원 배열을 변수 2~3개로 축소)이 필요하면 Bottom-up으로 전환한다.
활용: 배낭 문제(Knapsack), 최장 공통 부분수열(LCS), 편집 거리, 동전 교환 문제, 타일링 문제.

가장 긴 증가하는 부분 수열Longest Increasing Subsequence (LIS)

주어진 수열에서 순서를 유지하며 증가하는 가장 긴 부분 수열의 길이를 구하는 문제. 기본 DP는 O(n²)이며, 이분 탐색을 결합하면 O(n log n)으로 개선된다.

기본 DP — O(n²)

// dp[i] = arr[i]를 마지막 원소로 하는 LIS의 길이
int lisDP(int[] arr) {
    int n = arr.length;
    int[] dp = new int[n];
    Arrays.fill(dp, 1);            // 자기 자신만으로도 길이 1
    int maxLen = 1;
    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (arr[j] < arr[i]) {
                dp[i] = Math.max(dp[i], dp[j] + 1);   // arr[j] 뒤에 arr[i]를 이어붙일 수 있으면 갱신
            }
        }
        maxLen = Math.max(maxLen, dp[i]);
    }
    return maxLen;
}

이분 탐색 결합 — O(n log n)

// tails[k] = 길이 k+1인 증가 부분수열 중 "끝값이 가장 작은" 값 (실제 수열이 아님에 주의)
int lisBinarySearch(int[] arr) {
    List tails = new ArrayList<>();
    for (int num : arr) {
        int lo = 0, hi = tails.size();
        while (lo < hi) {                 // num이 들어갈 위치를 이분탐색 (lower_bound)
            int mid = (lo + hi) / 2;
            if (tails.get(mid) < num) lo = mid + 1;
            else hi = mid;
        }
        if (lo == tails.size()) tails.add(num);   // 모든 값보다 크면 새로 추가 → 길이 1 증가
        else tails.set(lo, num);                   // 아니면 해당 위치 값을 더 작은 num으로 교체 (미래 확장 가능성 ↑)
    }
    return tails.size();
}
기본 DP O(n²)
이분탐색 결합 O(n log n)
주의: tails 배열은 실제 LIS 수열이 아니라 "길이별 최소 끝값"을 담을 뿐이다. 실제 수열 복원이 필요하면 별도로 각 원소가 갱신될 때의 인덱스를 추적해야 한다.
활용: 박스 쌓기(2차원으로 확장), 최장 감소 부분수열(배열을 뒤집어 LIS 적용), 편집 거리와 결합한 응용 문제.

누적합Prefix Sum

배열의 구간 합을 반복적으로 질의해야 할 때, 매번 O(n)으로 더하지 않고 prefix[i] = arr[0]+...+arr[i-1]을 미리 계산해두면 임의 구간 합을 O(1)에 구할 수 있다. DP의 가장 단순하면서도 실전에서 가장 많이 쓰이는 형태 중 하나다.

// 1차원 누적합
int[] buildPrefixSum(int[] arr) {
    int n = arr.length;
    int[] prefix = new int[n + 1];        // prefix[i] = arr[0..i-1]의 합, prefix[0] = 0
    for (int i = 0; i < n; i++) {
        prefix[i + 1] = prefix[i] + arr[i];
    }
    return prefix;
}
int rangeSum(int[] prefix, int l, int r) {  // [l, r] 구간 합 (0-indexed, inclusive) — O(1)
    return prefix[r + 1] - prefix[l];
}

// 2차원 누적합 — 부분 직사각형 합을 O(1)에 구함
int[][] build2DPrefixSum(int[][] mat) {
    int n = mat.length, m = mat[0].length;
    int[][] prefix = new int[n + 1][m + 1];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            // 포함-배제 원리: 위쪽+왼쪽-왼위(중복 제거)+현재값
            prefix[i + 1][j + 1] = prefix[i][j + 1] + prefix[i + 1][j] - prefix[i][j] + mat[i][j];
        }
    }
    return prefix;
}
int rectSum(int[][] prefix, int r1, int c1, int r2, int c2) {  // (r1,c1)~(r2,c2) 직사각형 합 — O(1)
    return prefix[r2 + 1][c2 + 1] - prefix[r1][c2 + 1] - prefix[r2 + 1][c1] + prefix[r1][c1];
}
전처리 O(n) (2차원 O(nm))
쿼리당 O(1)
활용: 다수의 구간 합 쿼리, 2차원 히트맵/이미지의 부분합, 차분 배열(Difference Array)과 결합한 구간 갱신 문제.
